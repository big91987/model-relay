# Model Relay：团队模型网关产品委托

## 来源与方向

用户要求将演示仓库升级为有真实产品场景的研发仓库：从零实现一个类似 New API 所在产品类别的大模型 API 中转站，禁止抄其实现。默认采用团队自用、单管理员、应用密钥接入的推荐方案；产品和技术普通选择记录后推进，不设置形式化阶段审批。平台研发和本产品实现分别维护，不向平台引擎写入产品业务规则。

## 首版可用闭环

管理员通过受支持的本地初始化命令创建管理员凭据并启动完整服务；在管理网页登录、接入一个 OpenAI 兼容上游（地址及服务端凭据）、配置对外模型别名与上游模型的映射、签发一个应用访问密钥。应用以该密钥查询模型并发起普通／流式对话。管理员查看每次调用的模型、状态、耗时和上游实际返回的 token 用量；禁用密钥或路由后新的调用停止。服务重启后配置、密钥状态和调用记录保留。

首版只承诺 GET /v1/models、POST /v1/chat/completions 的明确支持子集。至少支持 messages、model、stream，普通生成参数和工具调用字段应按协议透明转发或明确报错，不默默删掉。不要冒称兼容 Responses、Anthropic、图片、音频或所有厂商扩展。首版不做支付、充值、计价、多租户组织管理、多机 HA、自动跨渠道重试或复杂调度。

## 验收重点

1. 首次安装有明确的初始化、启动、管理页登录、健康检查和退出操作，不依赖改数据库。
2. 上游可新增、编辑、禁用；服务端保存的上游密钥加密，查询和错误中不回显。没有上游时页面真实显示待配置，不注入演示成功数据。
3. 管理员能创建模型别名并关联唯一上游的真实模型；应用只能调用已启用映射。多个上游及路由选择按后续路线交付。
4. 应用密钥仅创建时显示完整值，后续仅前缀／尾部标识；保存不可逆摘要；可禁用。无效、禁用密钥返回 401，不触达上游。管理会话与应用密钥的权限隔离。
5. 真正通过 HTTP 转发普通结果和 SSE 增量，不能缓冲整段才显示。客户端取消时中止上游；上游错误、超时、错误内容类型、流中断有可观测结果，不自动重复生成。
6. 请求记录包含请求标识、模型、状态、延迟和可得用量；未知用量显示未知，不以 0 或估算冒充上游用量。不记录完整提示词、回复或任何密钥。
7. 正常启动、错误配置、占用端口、重启保留数据和备份恢复有可重复验证；数据库演进使用明确版本迁移，不删除数据重建。
8. 管理 UI 简洁可用，包含概览、上游、模型、访问密钥、调用记录与一个调用测试入口；桌面和窄屏可操作，表单错误清楚，危险凭据不写浏览器持久存储。
9. 安全边界包含管理员鉴权、写操作来源校验、登录限速、请求大小限制、上游地址校验、拒绝重定向及凭据跨地址泄漏；默认监听 loopback。开发测试允许显式打开本地上游，仅影响隔离测试配置。
10. 自动测试用独立的协议测试上游验证真实 HTTP/SSE、错误和取消，浏览器使用真实后端；记录这是受控协议测试，不是付费供应商联调。未提供真实上游凭据不得伪称已联调；用户可通过正式管理页完成供应商接入。

## 当前增强与成功口径

第 1 项已交付的空配置 UI 闭环、一次性密钥、普通／SSE、同请求诊断、深链与会话恢复持续回归。Issue #18 本轮增加多个上游与同一公共模型多候选运营、可验证的优先级与同级权重、健康冷却恢复、有限切换和逐尝试诊断，并精简概览与分组业务／账户导航。保存、连接核验和生成成功分开；未知及多尝试消耗不伪装为健康或零用量。390px、桌面、键盘连续任务及真实旧数据升级是本轮 P0，完整 AC 和责任见当前 Run PRD，不另建项目级第二套需求。

成功依据为扩展后的固定 `make verify` 真实 Go 服务旅程与独立 QA；供应商凭据未提供时仅有受控上游证据。第 1 项完成不表示第 2–4 项或产品全量验收通过。项目维护者负责支持、安全和供应商费用授权；用户已授权本目标维护者核对 QA 后，通过既有 Connector／正式入口自主完成测试仓 PR 合并与测试部署，无需等待用户另行批准。阶段 Agent 仍按职责交付草稿 PR，未来发布按真实回执报告；平台源仓 PR 不在此合并授权内。
