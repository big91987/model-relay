## 委托与边界

按 [产品路线图](../roadmap.md) 第 1 项基础闭环及下述故事维护。后端、转发服务、管理 API、存储及运维命令全部用 Go。前端可用 HTML/CSS/JavaScript，由 Go 服务提供；不得使用 Node/Python 作为后端或转发运行时。既有 Go 依赖与存储契约保持，新增设计采用当前规模足够且可迁移的简单方案。

只做一个管理员、一个可配置 OpenAI 兼容上游、多个对外模型别名及多个应用访问密钥。上游可以修改和禁用，不要求 M1 支持多渠道调度。对外接口为 GET /v1/models 和 POST /v1/chat/completions，明确支持普通与 SSE 流式请求；不声称兼容尚未实现的协议。

## 用户故事与验收输入

| Story | 行为与结果 | 验收条件 |
|---|---|---|
| S1 管理员首次安装 | 通过受支持命令初始化并启动完整服务，登录管理网页 | 空目录可启动；初始化不能覆盖已有凭据和数据；默认只监听 loopback；登录鉴权和来源校验有效；健康接口可用 |
| S2 管理员接入模型 | 通过网页配置上游地址、服务端凭据和模型别名 | 凭据加密保存、查询不回显；普通调用方不能管理；无上游时显示待配置；禁用或未知模型拒绝；不向任意客户端指定地址转发 |
| S3 应用获取调用权限 | 管理员签发独立访问密钥，应用列出已启用模型并调用 | 完整密钥只显示一次；摘要存储；无效／停用密钥 401 且未访问上游；普通响应真实转发，生成参数和工具字段透明传递或明确拒绝 |
| S4 应用使用流式结果 | SSE 增量实时到达，客户端可以取消 | 第一批数据在上游结束前可见；保持合法协议；取消中止上游；流前／流中错误分别处理，不自动重发生成 |
| S5 管理员定位异常 | 从记录看请求标识、模型、时间、状态、延迟与实际用量 | 上游拒绝、超时、断流可区分；用量缺失显示未知；不记录完整提示词／回答、密钥或敏感上游响应；网页可查看真实调用记录 |
| S6 运营者保留数据 | 正常停止／重启，按说明备份并恢复 | 配置、密钥状态和记录保留；占用端口清楚失败；恢复验证使用隔离目录；版本迁移不靠删库；完整服务由同一 Go 入口运行 |

## 必需质量边界

管理员凭据、上游凭据和应用访问密钥各有权限边界；请求体限额、登录限速、上游地址校验、超时与取消、禁止跟随重定向、敏感错误脱敏必须进入设计和测试。公网暴露及生产运维配置不属于默认本地预览授权。

管理页包含清楚的配置入口和调用记录，可附最小调用测试入口。桌面和窄屏可用；实际后端未接通时不得用静态“成功”页面代替验收。

## 验证与交付

- Go 的标准构建、单元／HTTP 集成测试和 vet 入口必须可复现；用项目拥有的 verify 命令作为固定 Connector 入口。
- 使用明确标注的受控 HTTP 上游测试普通响应、SSE、请求取消、超时、错误、敏感数据和重启；这是测试夹具，不是产品默认上游，也不是真实供应商联调证据。
- 浏览器必须操作正在运行的 Go 服务；静态原型检查只算原型检查。原生 Agent 沙箱不能监听端口时，由已经配置的项目验证 Connector 执行真实测试并保留回执，不临时扩大权限。
- 未提供真实供应商凭据时明确留下“供应商联调未测”，交付可通过正式管理页配置后联调的服务。不得读取其他项目秘密或擅自消耗付费额度。
- 输出 PRD/G1、设计/G2、实施计划、实现、独立 QA、运行／备份说明和完整草稿 PR。不得把 M2–M4 做成阻塞 M1 的前置条件。
