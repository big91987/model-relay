# Model Relay 产品路线图

## 产品目标

Model Relay 是面向团队的大模型 API 中转站。管理员统一管理供应商接入和模型路由，应用使用平台签发的访问密钥调用；调用结果、用量及异常可追溯。作为独立正式产品持续迭代，不把演示数据、测试夹具或研发编排本身当作产品能力。

用户约束：后端全部使用 Go；从零原创，不参考或复制 New API 实现。首期运营模式按团队自用、单管理员推进，公开商业运营另立阶段需求。

## 阶段与退出标准

| 阶段 | 用户得到的结果 | 功能范围 | 退出标准 | 依赖／状态 |
|---|---|---|---|---|
| M1 / v0.1 基础中转可用 | 管理员接入一个上游，应用用自己的密钥完成普通及流式调用，重启后可继续使用 | Go 完整服务；最小管理网页；一个 OpenAI 兼容上游；模型别名；应用访问密钥；普通／SSE 转发；请求结果和实际用量；持久化；初始化、启动和备份 | 从空数据目录通过公开操作入口完成配置→签发→调用→查看记录→停用密钥→重启保留数据；相关错误／中断测试通过，独立 QA 有真实证据 | 当前阶段；交给研发 Pipeline |
| M2 / v0.2 多上游与可靠性 | 某个供应商不可用时可定位并按明确规则切换，不重复生成或计费 | 多上游；路由优先级／权重；健康探测；熔断恢复；限定条件的故障转移；请求并发及速率限制；按模型过滤诊断 | 两个真实或明确标注的受控上游验证路由分配、禁用、失败切换、恢复及流开始后不重放 | 依赖 M1；Planned |
| M3 / v0.3 团队治理与用量控制 | 团队成员可受控使用模型，管理员能追踪责任和限制消耗 | 用户／角色；应用及密钥归属；模型授权；额度／预算；实际用量统计、账目校核和导出；管理审计；数据保留策略 | 不同角色的正常／拒绝访问可验证；并发额度扣减不超支；未知用量明确处理；密钥轮换和撤销有闭环 | 依赖 M2；Planned |
| M4 / v1.0 协议与运营交付 | 支持已选定的更多调用方，并可稳定安装、升级和运维 | 根据实际客户需求选择 Responses／Anthropic／Embeddings 等协议；协议适配一致性；容器与环境配置；指标告警；版本迁移和灾难恢复；升级回滚指南 | 每个声明兼容的协议都有契约与真实联调证据；从旧版本升级保留数据，备份可恢复，运行故障可诊断 | 依赖 M3；Planned |

支付充值、公开售卖额度、多租户计费和多区域高可用不在上述版本的默认承诺内。只有运营模式或实际采用证据发生变化时重新定义范围，不能因参考产品包含这些功能就自动加入。

## 第一阶段功能包

功能包是 M1 内部的交付切片，不是四条独立重复的全流程。目前只向研发 Pipeline 提交一个 M1 需求，阶段 Agent 按依赖组织实现。

| 功能包 | 纵向结果 | 包含功能 | 验收重点 | 依赖 |
|---|---|---|---|---|
| M1-A 首次接入 | 管理员从空安装进入管理页并保存上游 | Go 服务骨架；配置与持久化；初始化凭据；登录；上游地址／凭据管理；健康检查 | 无硬编码生产密码；凭据不回显；非法配置拒绝；重启可读 | 无 |
| M1-B 首次成功调用 | 应用使用独立密钥通过模型别名得到上游结果 | 模型映射；应用密钥创建与停用；模型列表；普通 Chat Completions | 无效密钥不触达上游；管理／调用权限隔离；模型未知返回明确错误 | A |
| M1-C 流式和故障闭环 | 应用实时收到增量，能理解失败且不会重复执行 | SSE；取消／超时；上游失败映射；请求标识与状态／耗时／实际 token 记录 | 不缓冲完整流；取消结束上游；失败无成功伪装；没有用量就是未知 | B |
| M1-D 可安装可验收 | 新环境可按文档使用同一完整服务 | 构建／启动／停止指南；数据目录；备份恢复；迁移约定；管理 UI 操作与集成测试；发布说明 | 实际网页和 Go HTTP 测试；重启及恢复保留配置／密钥；未测供应商列明 | A–C |

## 研发与发布规则

- 产品路线图定义阶段目标；[M1 任务](releases/v0.1.0.md) 是本次 Pipeline 的唯一范围输入。
- Pipeline 生成当前任务的 PRD、设计、实现计划、测试和独立 QA 证据；这些文档不能把 M2–M4 提前变成 M1 必需项。
- 文档批准类普通选择按已授权的自动推荐推进，必要澄清和高风险权限操作单独处理。
- 用户决定产品验收及合并；阶段“完成”、草稿 PR 和测试通过不等于版本发布。
- 状态必须链接真实 Issue／Run／PR。源码未产生、外部联调未进行时如实标明，不因文档完整而宣称可用。
