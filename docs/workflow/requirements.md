# Model Relay v0.1 需求与验收基线

## 1. 目标、依据与成功标准

让团队管理员统一接入供应商，给应用签发独立访问密钥，使应用无需持有供应商凭据即可通过稳定模型别名调用，并让管理员能定位失败、停用访问和恢复服务数据。

依据：用户当前委托、`docs/releases/v0.1.0.md` S1–S6 与质量边界、`docs/roadmap.md` M1-A～D、`docs/product-brief.md`、`docs/workflow/task.md`。本次发布范围优先于产品委托中的多上游方向。仓库当前只有范围资料，没有实现、测试回执或供应商响应；直接调用供应商是当前替代路径，采用规模和量化收益尚无实测依据。

成功标准：从空数据目录，经正式入口完成初始化→登录→接入上游和模型→签发密钥→列出模型→普通/SSE 调用→查看真实记录→停用→重启→隔离备份恢复；以下所有 P0 AC 有真实证据，`make verify` 实际成功且独立 QA 完成。文档就绪、测试夹具成功和草稿 PR 均不等于供应商联调、用户最终验收或正式发布。

## 2. 用户、运营方式与价值流

- 单管理员兼任团队运营、费用和安全责任人：初始化、保管管理凭据和恢复材料，通过网页配置供应商、维护模型、签发/停用应用密钥、查看异常，按运行指南停止、备份和恢复。
- 应用调用方：从管理员取得密钥，通过中转接口查询模型并调用；不读取供应商凭据、不执行管理动作。密钥丢失或疑似泄露时向管理员申请新密钥并停用旧密钥。
- 上游供应商：提供兼容的生成与用量响应；其可用性、账单和协议扩展属于外部依赖。供应商联调和付费消耗需要另有凭据及授权。
- 产品：提供接入、转发、访问控制、调用追踪和数据保留。管理员人工处理供应商故障、配置错误和密钥退出，不承诺自动调度、自动补偿或生成重试。

核心闭环：管理员通过本地正式命令建立安装及管理身份；网页接入一个上游、建立多个模型别名并签发多个应用密钥；应用用自己的密钥获取启用模型、请求普通或流式生成；产品记录结果；管理员依据记录调整配置或停用访问；停止、重启和恢复后继续同一闭环。退出以停用密钥或模型/上游阻止新调用，不要求删除历史记录。

## 3. 范围、默认值和业务不变量

本节及 AC 全部为 P0，不引入独立 P1 功能包。普通默认值依据已有自动推荐授权直接采用，无需再次阶段审批。

| 对象/能力 | 本次结果与生命周期 | 默认值/不变量 |
|---|---|---|
| 安装与管理身份 | 空目录初始化、启动、登录/退出、停止、重启、备份/恢复 | 一个管理员；无硬编码生产密码；重复初始化不覆盖已有数据；数据独立于源码 |
| 上游接入 | 未配置→网页保存→通过调用核验→编辑/禁用 | 一个可配置 OpenAI 兼容上游；无默认假供应商；应用不能选择目的地址；改地址不自动携带旧凭据到新地址 |
| 模型别名 | 管理员创建、映射真实模型、编辑/禁用 | 多别名，每个只绑定一个明确上游模型；别名唯一；应用只见可用映射；停用立即影响后续新请求 |
| 应用密钥 | 管理员签发、一次展示、交付应用、停用 | 多密钥，不可逆摘要保存；完整值只在创建结果中展示；丢失后重新签发，不可找回 |
| 调用 | 鉴权/验证→一次转发→成功、拒绝、失败、超时或取消→记录 | 不自动重放生成；在途请求不因后续配置变更切换目的地；停用不承诺追溯取消已开始调用 |
| 调用记录 | 生成、持久化、管理员查看、随备份恢复 | 默认不记提示词、回答或凭据；实际用量可为未知；不把缺失用量写成 0 或估算 |
| 管理网页 | 概览、上游、模型、密钥、记录、最小调用测试入口 | 同一 Go 服务提供真实网页和 API；测试入口使用明确输入的应用密钥并走同一调用规则，不绕过鉴权、不自动调用付费上游 |

对外承诺仅 `GET /v1/models`、`POST /v1/chat/completions` 的明确子集，至少支持 `model`、`messages`、`stream`。常见生成参数及工具调用字段须透明转发或在转发前明确拒绝，不得静默丢弃。设计提供明确兼容清单和错误契约，不宣称全部厂商扩展兼容。

默认监听 loopback，推荐预览端口 5544；自动测试使用随机端口及隔离临时目录。开发测试可显式允许本地测试上游，但不能成为产品默认配置。请求限额、登录限速、超时等必须是明确可测试的规则，具体阈值和兼容细节由设计基于团队自用场景记录，不在需求阶段选择底层组件或编造吞吐 SLA。

## 4. User Story 与可验证验收标准

验收执行责任：开发提供自动化测试、运行说明及真实 `make verify` 回执；独立 QA 检查代码版本一致性、重现关键闭环并评估失败覆盖；用户保留最终验收及合并决定。以下 HTTP 场景使用显式标注的受控上游，检查实际收到的请求、次数、取消及发送时序，不以静态网页或直接改数据库代替正式操作。

### S1 / M1-A：管理员首次安装

作为管理员，我能从空目录开始使用完整服务，且不会破坏已有安装。

- AC-01：按指南使用公开初始化与启动入口，空目录创建管理凭据及必要持久数据，默认仅 loopback 可达；健康接口返回可用状态，管理页初始显示未配置，不显示伪造成功或调用记录。重新执行初始化明确拒绝覆盖，原凭据仍能登录且原数据不变。
- AC-02：正确凭据登录后可管理，错误凭据不能登录；未登录请求不能读取管理数据或写入配置；退出后原会话失效。管理会话不能替代应用密钥访问调用接口，应用密钥不能访问管理接口。
- AC-03：超过设计声明的登录限速受到限制；管理写操作拒绝不可信来源且数据不变；错误响应和日志不泄露口令/会话。测试覆盖缺少来源信息的处理规则，不允许通过省略来源校验绕过保护。

### S2 / M1-A、B：管理员接入模型

作为管理员，我能维护唯一上游及其模型映射，并明确知道何时可调用。

- AC-04：网页保存上游地址和凭据、创建至少两个不同别名后，刷新和重启仍可见配置；有效调用在上游观察到对应真实模型与正确认证。编辑后新请求使用新配置；禁用上游/别名后新请求明确拒绝且上游计数不增加；重新启用后可恢复调用。重复别名或无效映射明确拒绝，不破坏原配置。
- AC-05：非法地址、禁止的协议/地址范围及客户端指定的转发目的地被拒绝；测试包含本地/私有目的地址默认拒绝、显式隔离测试例外和重定向。重定向目的地未收到认证凭据或请求；编辑目的地址不把原凭据自动发送给新目的地。设计明确地址解析、重新解析及校验时机以防地址校验绕过。
- AC-06：上游凭据加密保存，管理查询、页面刷新、错误及日志不返回完整值；留空编辑行为和更换凭据规则明确，不能意外清空或泄露原值。静态存储检查结合实现审查证明不是明文/可逆编码冒充加密；测试证据使用哨兵凭据且脱敏，不附真实秘密。

### S3 / M1-B：应用获取权限并普通调用

作为应用调用方，我能用独立密钥得到真实结果，且拒绝不会产生上游消耗。

- AC-07：网页签发至少两把密钥，仅签发结果完整展示；刷新/查询只返回不可用于认证的标识，持久化只保存不可逆摘要。停用一把后其新调用返回 401 且不访问上游，另一把仍可调用；无密钥、无效密钥同样返回 401，不泄露密钥是否存在的敏感信息。
- AC-08：有效密钥查询模型列表只得到已启用、可路由的别名，无模型时为空列表；未知或禁用模型调用明确拒绝，不触达上游。普通请求实际通过 HTTP 到达配置上游，模型正确转换，返回真实生成内容与可得用量，不以模拟成功替代结果。
- AC-09：兼容清单中生成参数和工具字段到达上游且结果不被悄悄删改；清单外不支持字段明确拒绝或按声明透明传递。畸形请求、缺少必填内容和超过声明大小的请求明确拒绝且不触达上游；失败不产生成功响应。

### S4 / M1-C：应用流式调用、取消和失败

作为应用调用方，我能及时得到增量，并在失败时知道本次未完整完成。

- AC-10：上游发送首个 SSE 增量后等待一个受控屏障才发送剩余增量；客户端必须在屏障释放、上游结束前收到首个增量。测试验证合法 SSE 内容类型、事件顺序和结束标记；不得缓冲完整响应才交付。正常流含工具增量时遵循设计兼容声明。
- AC-11：客户端在普通等待或流中主动断开，测试上游观察到请求取消/连接终止，服务不继续读取完整生成；请求记录标记取消且不记成功。取消等待有设计声明的有限测试截止时间，无任何自动重放。
- AC-12：受控上游分别模拟认证拒绝/限流/服务失败、建立连接失败、错误内容类型、等待超时、流中错误和未正常结束的断流。流开始前返回明确非成功错误；流开始后不尝试重写已发送 HTTP 状态，按设计错误/终止契约结束，记录失败类别且客户端不能把它当作正常完成。每个场景上游最多收到一次生成请求，错误内容和日志脱敏。

### S5 / M1-C：管理员定位异常

作为管理员，我能用记录区分失败与成功，而不泄露团队对话或伪造用量。

- AC-13：实际调用后，网页与持久记录能关联请求标识、请求时间、请求模型、结果状态、耗时及可得实际用量；至少区分成功、上游拒绝、上游失败、超时、取消和流中断。转发前拒绝的记录策略由设计列明且可验证，不能以缺少应用身份编造归属；记录不可被调用方枚举。
- AC-14：普通及 SSE 有真实 usage 时按上游值记录；未返回、缺字段、取消或断流未得到 usage 时对应值显示未知；上游明确返回 0 与未知可区分。测试覆盖部分用量，禁止将估算或所有缺值补 0 当作实际值。
- AC-15：含哨兵提示词、回答、各类凭据及敏感上游错误的调用完成后，检查日志、管理响应、页面记录与持久调用记录不包含这些完整秘密/对话内容。上游响应中的诊断信息仅按设计白名单或脱敏规则保留；浏览器持久存储不保存危险凭据。

### S6 / M1-D：运营者停止、重启和恢复

作为运营者，我能保留可用安装，使用文档恢复，而不靠改数据库。

- AC-16：已有配置、两把不同状态的密钥及成功/失败记录，正常停止并重启后全部保留；原启用密钥仍能调用，停用密钥仍返回 401，记录内容一致。错误配置、缺失恢复必需材料及端口占用明确失败、不静默换端口，不覆盖原数据。
- AC-17：按指南从停止后的安装备份，再恢复到独立目录，保留配置、管理员登录能力、密钥状态和记录；恢复实例能实际调用且禁用状态有效。指南说明凭据解密所需材料及敏感备份保管责任；缺失材料不能显示假恢复成功。设计给出数据版本和迁移失败行为，拒绝以删库重建迁移；不提前实现 M4 的完整升级/回滚系统。
- AC-18：桌面与窄屏浏览器操作运行中的 Go 服务，完成登录、配置、模型、签发/停用、调用测试及记录查看；表单错误可见且不显示未保存的成功状态。测试入口普通/SSE 请求遵循相同鉴权、记录和取消规则，不持久保存输入密钥或对话；静态原型检查不算此项通过。
- AC-19：项目固定入口 `make verify` 检查格式、执行 `go vet`、单元测试、真实 HTTP 集成测试与构建；任一步失败整体非零退出。使用锁定 Go 模块、临时目录及随机端口，不读写用户数据或调用用户/付费上游。保存实际命令、退出码、测试输出及代码版本标识；缺失运行回执不能标记通过。

## 5. 非目标、依赖和风险

- 不做 M2–M4：多上游调度、自动故障转移、并发/用量额度治理、用户角色、多租户、支付计费、更多协议、生产部署、多机 HA、完整商业运营及升级回滚平台。基础登录限速和请求大小限制不扩展成 M2 的业务流控。
- 后端、管理 API、代理、存储和运维命令均为 Go；前端允许 HTML/CSS/JavaScript，由 Go 服务提供。原创实现，不读取、复制或改编 New API 代码、数据结构或资产；具体组件、接口/数据结构及 Go 版本留给设计。
- 真实供应商响应及凭据尚未提供，状态为“供应商联调未测”。受控测试证明协议行为，不证明供应商实际兼容或服务可用；设计和交付须列出兼容声明及正式管理页联调路径。不得擅自使用付费额度或读取其他项目秘密。
- 安全风险集中在上游地址与凭据泄漏、管理写操作及浏览器密钥暴露；设计必须覆盖认证隔离、来源校验、地址校验/重定向、加密材料管理、限额、有限等待和取消，不能以团队自用省略。
- SSE 成功结束和用量依赖上游，流中失败无法撤销已交付增量；界面及记录须如实表达部分结果，禁止自动重放。运行中异常退出留下的未完成记录处理及记录写入失败的可观察行为由设计定义。
- 本机预览授权不包含公网暴露；当前不承诺具体吞吐/可用率。新增运营模式或真实采用规模变化时重新定义后续阶段，不增补当前验收门槛。
- 如 Agent 沙箱无法监听，保留失败/限制证据，使用已配置的 host-only 项目验证 Connector 获得真实 `make verify` 回执；不扩大权限，不将静态检查代替 HTTP/浏览器验收。Git 分支、提交、推送和草稿 PR 由 Connector 执行。

## 6. G1 自查记录

结论：需求基线可进入设计。状态：`Ready for Architecture`，依据用户已明确委托的普通选择自动推进授权；此状态不表示实现或发布验收通过。

- 已满足：目标与证据、角色及人工运营责任、首次接入到退出/恢复闭环、对象生命周期与不变量、M1 切片和非目标均明确；S1–S6 对应 AC-01～19，正常、拒绝、取消、异常、安全和恢复都有可观察判据与验收责任。
- 非阻塞缺口：真实供应商兼容及规模未实测；通过显式联调未测标记、受控测试和不承诺吞吐 SLA 管理，不伪装为已验证。
- 阻塞项：无；没有需要用户裁决的方向性冲突。单上游以本次发布范围为准，最小调用测试入口按既有自动推荐纳入。
- 带入设计：Go 全栈后端约束；兼容子集、流结束/失败契约、用量未知表达；安全及阈值规则；一次转发和取消；数据保留、加密材料与停止备份；异常未完成记录/记录写入失败处理；真实 UI 和固定验证入口。具体选型、契约和实现任务不在本节点预决。
- 建议：继续设计/G2，然后实现、真实验证及独立 QA，最后由 Connector 交付草稿 PR；当前仅完成需求定义，无代码、运行或供应商联调通过声明。
