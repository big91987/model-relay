# Model Relay v0.1 任务入口判断

## 目标与依据

从零实现团队自用、单管理员的真实 Go 大模型 API 中转站，仅执行 `docs/roadmap.md` 的 M1-A～D 和 `docs/releases/v0.1.0.md`。用户明确要求先需求、再设计、开发、独立 QA，真实执行 `make verify` 后交付草稿 PR；普通产品和技术选择按推荐记录并自动推进。

仓库核对结果：已有 README、路线图、v0.1 发布范围和产品委托；尚无产品源码、Go 模块、Makefile 或本次 requirements/design 文档。当前是新产品首版，不是已有行为的局部修复；现有故事是需求输入，不是已完成的 PRD/AC 或架构设计。前序 Connector 已准备分支并创建 Issue #1，本节点不重复执行 Git/GitHub 操作。

## 现状与预期行为

现状仅有文档，无可运行服务，也无测试通过或供应商联调证据。预期从空数据目录经公开初始化命令启动 Go 服务，管理员登录管理网页配置上游与别名、签发应用密钥；应用查询模型并完成普通和实时 SSE 调用；管理员查看真实调用记录、停用密钥；服务重启后配置、密钥状态和记录保留。

## 范围与非目标

- 一个可修改、禁用的 OpenAI 兼容上游，多个模型别名、多个应用密钥；管理网页与后端由同一 Go 服务提供。
- 对外仅 `GET /v1/models` 与 `POST /v1/chat/completions` 的明确支持子集；生成参数与工具字段透明转发或明确拒绝，不静默丢弃。
- 包含持久化、初始化、健康检查、正常停止、重启和备份恢复；默认 loopback，推荐预览端口 5544。存储、Go 版本及契约留给设计阶段确定。
- 包含管理员与应用鉴权隔离、写操作来源校验、登录限速、请求限额、上游地址校验、凭据保护、禁止重定向、超时、取消、流中断处理及错误脱敏；不自动重试生成。
- 记录请求标识、模型、状态、时间、耗时和上游实际用量；缺失用量标记未知，默认不记录提示词、回答或凭据。
- 不做 M2–M4、多渠道调度、团队角色治理、计费支付、多租户、额外协议或生产部署；不读取、复制或改编 New API 实现。
- 产品委托中的多上游方向不扩展本次范围，以 v0.1 的单上游约束为准。最小调用测试入口按推荐纳入需求细化，不引入额外协议。

## 验收依据与证据要求

以 v0.1 的 S1～S6、必需质量边界及路线图 M1 退出标准为基线，需求阶段形成可验证 AC，设计阶段定义实现与接口契约：

1. 空目录初始化不能覆盖已有数据；管理页配置→签发→普通/SSE 调用→查看记录→停用密钥→重启保留数据形成闭环；占用端口明确失败，隔离目录验证备份恢复。
2. 密钥仅创建时完整显示、摘要存储；上游凭据加密且不回显；无效或停用密钥返回 401 且不触达上游；禁用或未知模型明确拒绝。
3. SSE 首批数据在上游结束前到达，客户端取消中止上游；覆盖流前/流中失败、拒绝、超时、断流与敏感信息保护，无自动重放。
4. 管理 UI 在桌面和窄屏操作真实后端，表单错误清楚；静态原型不能作为端到端通过证据。
5. 后续实现项目固定入口 `make verify`，覆盖格式检查、`go vet`、单元与真实 HTTP 集成测试及构建，使用锁定 Go 模块。测试使用隔离临时目录、随机端口与明确标注的受控测试上游，不触达用户配置或付费供应商。
6. 开发和独立 QA 保留实际验证回执、失败证据及代码版本一致性；沙箱不能监听时由配置好的项目验证 Connector 执行，不扩大权限。本节点不执行实现验收，也不宣称测试通过。
7. 未提供凭据和实际供应商响应时标记“供应商联调未测”。不得提交凭据、数据库、个人会话、绝对本机路径或含秘密的运行证据。

## 起点选择与后续交接

选择 `requirements`：用户明确指定先需求与设计，且新产品需要把范围输入落实为本次 PRD/AC，再由设计确定存储、安全和协议契约。现有资料足够进入需求阶段，无须重复请求阶段批准。

跳过阶段：无。需求与设计均必要，不直接进入开发；本节点只做入口判断，不补造 PRD、设计或测试产物。后续依次需求、设计、开发、独立 QA，Git 提交、推送与草稿 PR 仍由授权 Connector 负责。

适用资料：`docs/roadmap.md`、`docs/releases/v0.1.0.md`、`docs/product-brief.md`。后续阶段产物分别存放 `docs/workflow/requirements.md`、`design.md`、`delivery.md`、`qa.md`、`pr.md`，仅在实际执行对应阶段时创建。
