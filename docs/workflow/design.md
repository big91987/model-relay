# 管理台运行服务版本：实现设计 / G2

## 1. 基线与整体影响

本次基线是 `docs/workflow/requirements.md` AC-01～08、`docs/workflow/task.md` 与平台交接的用户澄清。展示位置、来源、失败行为已经确认，不再重复访谈。本文替换历史 v0.1 总体设计作为此次局部改动的设计；历史设计可从 Git 追溯，既有 delivery、qa、pr 与日志不作为本次验收证据。

目标：管理员登录后在概览确认当前实例自报的运行版本。保持现有 Go 服务、嵌入式管理台、登录与权限边界，仅新增只读展示与相应回归；不增加数据库、管理接口、供应商调用、轮询、发布能力或部署。版本只能证明实例自报值，不证明构建标记正确或所有实例一致。

采用架构 Skill 的上下文恢复、最小设计、责任边界、故障与质量属性、自查部分；此功能不涉及新的平台领域或组件选型，不加载额外领域专家，不引入组织级运营模型、ADR 或第二套原型。

## 2. 用户路径与界面

1. 未登录时沿用登录页，不展示或主动获取新增运行版本。
2. 登录成功或恢复有效会话，进入概览时启动一次健康请求；原有概览信息独立加载。
3. 在概览标题「连接与访问」下、现有 `#summary` 前放一行「运行版本：加载中」；结果到达后仅更新值为原始版本或「版本未知」。顶部静态品牌标签不改为运行版本来源。
4. 离开概览隐藏该行并取消当前版本请求；重入概览清除旧值并再次请求。页面刷新后按既有会话检查流程进入概览并重新获取。
5. 退出开始即失效当前版本请求，实际 `signedOut()` 也执行清理；登录页不能显示上次版本。下一次登录重新获取。

建议值节点使用 `#runtime-version`，外层使用普通段落、值节点 `role="status"` / `aria-live="polite"`。默认 HTML 值为「加载中」，不嵌入构建值。有效字符串通过 `textContent` 写入，保留其内容、不添加 v 前缀。值节点局部使用 `white-space: pre-wrap; overflow-wrap: anywhere`，保留空白并使长文本在 390px 窄屏换行，不插入 HTML、不裁剪有效值。使用已有字体、颜色与段落间距，不新增卡片体系或交互控件。

## 3. 模块、接口与状态

| 位置 | 本次责任与预期修改 |
|---|---|

| `internal/relay/web/app.js` | 增加小型版本加载/失效逻辑，接入概览导航、退出与会话失效；不重构其他页面。 |
| `internal/relay/web/style.css` | 仅补版本值的保留空白与长字符串换行规则。 |
| `internal/relay/server.go`、`cmd/model-relay/main.go` | 沿用现有 `/healthz` 和 `Config.Version` / `buildVersion` 来源，默认 `dev`；预期不改生产后端。 |
| `tests/browser/ui.test.mjs` | 扩展现有 VM/DOM 与 fetch 桩回归；不引入产品依赖。 |
| `tests/browser/journey.mjs`、现有 Go HTTP 测试 | 实际服务一致性、浏览器展示/恢复/失败隔离及健康接口契约回归。 |

事实链：服务启动传入 `buildVersion` → `Config.Version` → 现有 `/healthz` JSON 的 `version` → 概览文本。管理员没有写入版本的命令，本任务也不新增版本资产或编辑能力。

版本使用独立的同源 `GET /healthz`，设置 `cache: 'no-store'` 避免浏览器复用缓存。不使用现有 `api(path)`：它固定前缀 `/admin/api/` 且 HTTP 401 会退出会话，健康请求失败必须独立降级，不引发退出。健康请求不发送管理 CSRF 请求头，不变更服务鉴权或现有健康接口访问策略。

版本局部状态只有：加载中、已知、未知，以及失效后的隐藏状态。每次导航先取消并失效上次版本请求；进入概览同步清除旧值为「加载中」，发起新请求，再按原有 `load(view)` 加载管理信息。版本 Promise 不得被 `load(view)`、`navigate(view)` 或 `Promise.all` 等待，因此即使健康请求悬挂也不延迟原有概览显示或导航。只对版本节点做局部状态更新，不调用全局 `message()` 或覆盖 `#summary`。

每个版本请求持有独立 AbortController、一次请求身份及启动时的 `navigationVersion` 快照；不得复用调用测试的 `aborter`。写回前同时核对：当前请求身份未失效、导航快照一致、`active === 'overview'`、控制台仍为登录状态。切页、重入、退出或会话失效先使请求身份失效，再 abort 并清理计时器与版本内容。无论取消是否及时生效，旧响应、旧异常及旧 finally 都不得修改当前版本或清理新请求的状态。

## 4. 存储、等待与错误边界

- 版本仅在当前页面内存/DOM 中保留；不写 localStorage、sessionStorage、数据库、URL、日志或配置，无迁移与新凭据。
- 推荐等待上限 **5 秒**，从发起请求计时，覆盖响应头与 JSON body 读取。到期立即使本次请求失效，若仍是当前登录概览则显示「版本未知」，随后 abort；不只等待 abort 抛错才降级。浏览器后台计时器可能被节流，5 秒是前台交互目标，不是严格实时保证。
- 响应非成功 HTTP、网络错误、不可解析 JSON、null/数组/非对象响应、字段缺失、非字符串、空字符串及仅空白字符串统一为「版本未知」。用 `trim()` 仅判空，对合法字符串显示未经 trim 的原值；`dev` 是有效值。
- 本次成功或失败结算后清理计时器；超时后迟到成功不得把未知改回已知，恢复必须通过新一次重入或刷新请求。主动切页/退出导致的取消不在别处显示错误。
- 健康请求即使返回 401 也只影响版本，不调用 `signedOut()`；真正管理 API 的会话失效仍按既有行为退出并清理版本。
- 版本失败不掩盖概览原有配置/存储状态或其他页面管理结果，不启用轮询或隐藏重试。服务真实存储故障可能同时导致健康与管理接口失败，本功能不承诺故障服务的管理操作成功。

在现有测试入口中添加回归，不建立第二套验证门禁。测试全部使用临时目录、临时端口与标明用途的受控响应，不访问用户供应商、不修改用户数据。

| AC | 最小新增证据 |
|---|---|
| AC-01 | 登录前不发健康请求且无可见运行版本；登录/会话恢复后可见；其他页面与退出后不可见。 |
| AC-02 | Go HTTP 回归检查 Config.Version 的发布样式值与 `dev` 原样返回；真实 Go 服务浏览器比较 `/healthz.version` 与节点 `textContent`；含首尾空白的有效值不被改写。 |
| AC-03 | 确定性逐项测试网络 reject、非成功 HTTP（含 401/503）、缺字段、空串、仅空白、非字符串、非法 JSON、null/数组响应；先成功后失败不能残留旧值。 |
| AC-04 | 将健康请求单独挂起，管理接口正常返回；未释放健康请求时 `#summary` 已可见且可切换模型页；健康失败不退出登录、不覆盖全局管理消息。 |
| AC-05 | 未知→离开→重入→新版本；成功→失败→未知；实际浏览器有效会话刷新发出新健康请求并恢复。检查请求次数，无自动轮询。 |
| AC-06 | 可控制的迟到响应覆盖概览→其他页、概览→其他页→概览、退出及重新登录；模拟忽略 abort 的旧成功/失败；可控计时器覆盖 5 秒超时（含 JSON body 悬挂）、超时后迟到响应及旧 finally 清理隔离。 |
| AC-07 | HTML 特殊字符仅作为文本，无新增元素/脚本执行；390px、1280px 展示，长字符串不导致页面横向溢出，标签与状态可访问。 |
| AC-08 | 实现节点运行固定 `make verify`，记录本次代码标识、命令、真实退出结果与失败证据，交独立 QA 核对全部 AC；Hook 回写原 Issue，Connector 提供草稿 PR，不部署。 |

现有 `make verify` 包含证据检查、格式检查、Go modules 验证、vet、前端 Node 测试、Go race/HTTP 测试、build 和启动 Go 服务的 Playwright 浏览器旅程。前端 VM 测试桩需补齐新增节点、fetch options/signal 与计时器能力；真实旅程保留至少一条未拦截的健康响应一致性检查，其余失败路径可针对 `/healthz` 单独拦截。已有完整旅程含受控上游测试，但不是此次版本功能的供应商验证；新增版本断言不发送模型请求。

设计不修改产品代码，不执行 `make verify`，不宣称 AC 通过。运行限制、缺依赖或失败需保留真实证据；若沙箱不能完成监听验证，由固定主机验证 Connector 提供回执并交独立 QA，不能把静态 browser.check 计作真实服务通过。

## 6. 推荐决策与风险

推荐方案已按自动推荐委托采用：在现有概览增加文本行、独立请求与局部超时/取消控制。理由是现有来源与导航已足够，新增框架、后端接口或持久化只会扩大故障与维护范围。5 秒允许短暂健康检查抖动且不会让用户长期等待；由于主路径不等待健康请求，该值不控制管理导航速度。

主要剩余风险是实现遗漏 body 阶段超时、只依赖 abort 而未防迟到响应，以及退出后重新登录复用了旧请求身份。对应验证见 AC-04～06；未发现需要退回需求的矛盾。缓存仅在客户端请求侧禁用，不新增服务端协议；版本自报准确性与多实例一致性仍不在范围。

不制作静态原型：现有页面仅增加一行文本，状态与定位已经足够明确，正式应用与实际 Go 服务验证由研发负责。不为凑流程生成原型验收或更新历史交付证据。
