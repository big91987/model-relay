管理员为同一公共模型配置多个上游后，希望可以启用“低延迟优先”，让正常流量逐步倾向近期响应更快的合格上游，并能在请求诊断中看见选择依据。当前已有优先级、固定权重和故障冷却，本次在这些能力上增加一种可选路由策略；已有权重策略继续作为默认和效果对照。

## 用户结果与边界

- 在现有路由管理页面选择权重策略或低延迟优先；保存、重新进入、服务重启和旧数据升级后行为明确。通过页面配置两个以上同模型上游，调用并查看同Request ID的选择、日志和费用结果；桌面及390px均可连续完成。
- 只在当前模型已授权、启用、健康、符合优先级和原有约束的候选之间选择；保持租户/Key隔离、额度、非零RPM/TPM、并发和金额预算规则，不能互相替代。
- 使用近期正常请求观测，说明普通响应与SSE的延迟口径，避免把输出长度造成的完整生成时长差异当选路收益。没有样本、样本过期、新候选、变慢和恢复应有可解释的有界行为，不永久饿死候选，不额外发起隐藏付费探测。
