# 需求与验收基线：交付工作台退出按钮配色与已证测试夹具修复

关联：Issue #118；沿用 #115 验收；#117 同版补丁完整回归一次通过，#116 同一补丁已完成独立 QA。
目标基线：`70a4f55b5cfd737e0882936ab8f65bbd66fcaed2`。

## 1. 背景与问题

交付工作台右上角「退出」按钮与普通操作按钮配色相近，用户浏览顶栏时不易辨认。需要让该按钮在常态与悬停态下具备明确可辨的浅红配色，同时不改变其位置、文字、键盘可达性和退出登录行为。

## 2. 范围

本次只交付两项内容：

1. **退出按钮配色**（产品变更）：`internal/relay/web/workspace.css` 中为 `#logout` 增加常态与悬停配色。
2. **Go 夹具就绪竞态修复**（测试基础设施）：`tests/verify/main_test.go` 的 `TestFixedRunnerReceipts` 夹具改用「临时文件 + mv」原子发布就绪回执、以轮询等待回执完整，并把 `timeout_gate` 场景的夹具门限从 200ms 提升到 5s、父预算从 8s 提升到 15s。采用 #117 已通过完整回归的同一版本；生产门限（`gateTimeout` = 25 分钟）与清理断言全部保留。

## 3. 业务规则（已确认，直接复用 #115/#117）

- 常态：底色 `#fff1f2`，文字 `#9f1239`。
- 悬停：底色 `#ffe4e6`；移开后恢复常态底色。
- 配色规则写在媒体查询之外，桌面与 390px 窄屏均生效且可辨认。
- 位置、文字「退出」、键盘焦点（`:focus-visible` 描边样式不变）与退出登录行为（POST `/admin/api/logout` 后返回登录页）全部保持不变。
- 其他按钮（如 `#nav-toggle`）配色与行为不变。

## 4. 非目标

- 不改动退出按钮以外的任何界面样式或交互。
- 不引入新功能、新页面或新接口。
- 不在本次范围内处理旧架构盘点发现；按新流程留在架构审查报告。
- 完整回归由固定节点执行，研发只做补丁核对与定向检查。

## 5. 验收条件（可验证）

1. `#logout` 计算样式：常态 `background rgb(255,241,242)`、`color rgb(159,18,57)`；悬停 `background rgb(255,228,230)`；移开鼠标恢复常态。
2. Tab 聚焦后 `#logout` 满足 `:focus-visible` 且描边为 solid，底色仍为常态色。
3. 配色断言在桌面宽度与 390px 窄屏下均通过。
4. `#nav-toggle` 计算样式保持原值（白底、深蓝灰字），其他按钮不变。
5. 点击「退出」仍调用 `/admin/api/logout` 并返回登录页。
6. 静态断言：配色规则位于媒体查询之外；`workspace.js` 中退出绑定与 fetch 调用保持原逻辑。
7. Go 测试：`TestFixedRunnerReceipts` 全部场景（含 `cancel_gate`、`timeout_gate`）通过；`timeout_gate` 回执记录的门限为 5000ms，断言中的生产门限期望仍为 25 分钟；夹具子进程清理断言保留并通过。
8. 项目验证入口（`make verify`：格式化、`go vet`、`go test`、构建）整体通过，完整回归由固定节点执行。
