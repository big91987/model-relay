# 首次配置、调用与诊断：需求基线

状态：Ready for Architecture（按用户自动推荐授权完成 G1，见 [评审](g1-review.md)）。仅表示需求可交设计，不表示实现或验收通过。

## 1. 背景、问题与证据

来源：用户最新 Issue #16 原始委托、入口交接及本会话补充的持续路线与测试仓合并／部署授权。基线 `d62cd51e8de2127548e1ac7469d349443d1bfe3d`；项目产品承诺见 [产品委托](../../../product-brief.md)，公共阶段及接续依赖唯一维护在 [路线图](../../../roadmap.md)，基础回归见 [v0.1.0](../../../releases/v0.1.0.md)。本文件只定义该 Run 的增强，不替换历史运行版本专项需求、设计或证据。

现状：管理员依靠 README 理解安装及协议，登录后在横向导航和简单表单之间手工串联上游、别名、密钥和调用；概览缺少数量和可执行步骤，模型／密钥空列表没有引导，测试手填别名，普通结果显示整个 JSON。调用结束后需要自行在记录中查找，没有同请求交接。这些缺口阻碍首次使用与失败恢复。证据来自现有 `internal/relay/web/index.html`、`app.js`、`proxy.go` 和固定 `Makefile` 的只读核对。问题频率与用户耗时尚未量化，不虚构采用率或提效百分比。

用户提供的基线已正式部署及 healthz 对应 SHA 属于入口事实；本节点未复验该部署。公开参考只用于行为与交互，观察和边界见 [参考记录](reference-observations.md)。

## 2. 目标、成功标准和非目标

一句话产品判断：团队管理员能从空业务配置通过控制台准备模型访问，完成真实可取消的调用，并找回同一请求的诊断结果。

本轮目标：G1 首次配置可完成；G2 状态与结果可信且可追踪；G3 敏感数据和失败生命周期受控；G4 控制台在桌面、390px 和键盘环境可用。这些是业务目标编号，不是评审 Gate 编号。

成功标准：下述全部 P0 Story／AC 有扩展后的固定 `make verify` 真实结果及独立 QA 对照；空业务配置中间步骤全程 UI 操作，普通与 SSE 均得到受控上游实际响应和对应真实记录，失败、取消与拒绝路径按规定核验。真实供应商未测单列。不得以文档、静态原型或历史回执替代新功能验证。

本轮非目标：多上游、路由优先级／权重、探活熔断／跨上游切换；权限／有效期／轮换／配额／业务限流治理；新增成员角色；新协议和安装升级系统；复杂全局统计；公开充值、支付、订阅计费、多租户销售、跨地域 HA。既有安全限额与运行／备份能力持续回归。

## 3. 用户、运营与责任

| 参与者 | 当前责任与获得服务的方式 | 支持、变更和退出 |
|---|---|---|
| 团队管理员／本机运营者 | 使用正式 `init`／`serve` 入口建立安装和管理员登录；通过 UI 接入合法供应商、创建别名、签发应用密钥、测试并核对记录 | 修改／停用上游和映射，启停密钥；处理配置错误、供应商授权和存储告警；通过正式退出／停止命令结束使用，保留数据 |
| 应用调用方 | 从管理员安全取得应用密钥，使用网关 Base URL 和公共别名，通过已支持协议调用 | 向管理员提供请求 ID 请求支持；授权结束由管理员停用密钥；不会获得管理权限 |
| 上游能力提供者 | 提供兼容接口、模型能力及合法供应商凭据，返回实际输出与可得用量 | 供应商故障／授权由管理员联系提供者处理；网关不承诺撤销已发生费用 |
| 目标项目维护者 | 对团队采用、容量、支持、风险及费用授权负责；已获用户授权，核对独立 QA 后自主完成测试仓 PR 合并与正式测试部署 | 按公共路线接续后续独立 Issue，无需用户重新发起；通过产品 Issue 处理支持与例外；平台问题交平台维护源修复，不手改运行数据库；平台源仓 PR 不在合并授权内 |

运营方式为团队自管、小规模单实例、单管理员，正式初始化在 UI 旅程之前。测试拥有独立空数据目录和随机端口；初始化管理员凭据可通过正式命令完成，但上游、别名和应用密钥不能以 API／SQL 预填。没有供应商凭据时管理员可在将来通过正式 UI 接入并联调，本轮只使用明确夹具。

## 4. 产品级业务架构与生命周期

价值流：进入控制台理解状态→接入唯一上游→准备公共别名→签发应用权限→执行普通／流式调用→核对同请求结果→修改配置或停用访问→退出。每个依赖缺失均给出对应操作入口，已完成步骤保持可访问。

| 核心对象 | 来源、首次可用与责任 | 生命周期与不变量 |
|---|---|---|
| 管理安装与会话 | 本机运营者按 README 正式初始化／启动后登录；成功进入控制台并可读取配置才有管理会话 | 登录→使用→过期／退出→重新登录；管理员密码与应用密钥权限隔离，退出清除浏览器敏感状态 |
| 唯一上游连接 | 管理员取得合法地址／凭据，在上游 UI 保存并启用；保存只确认配置，实际调用核验可用性 | 未配置→已保存启用／停用→调用成功／失败；地址或凭据变更后以前成功不证明新配置可用；服务端秘密不回显 |
| 公共模型别名 | 管理员在模型 UI 将公共别名映射到供应商模型；已启用且上游可用时可选择调用，实际响应才证明可调用 | 创建→编辑映射→启停；调用选择仅包含启用对象，不建立无作用占位对象；变更不篡改历史请求 |
| 应用密钥 | 管理员通过密钥 UI 签发并安全保管一次展示的完整值；使用该值调用核验 | 签发→启用／停用→遗失后重新签发并停用旧值；不可从列表找回完整值，只有安全标识进入诊断 |
| 测试调用 | 管理员选启用别名、输入已取得密钥及消息，明确发送；普通／SSE 使用同一网关代理 | 就绪→处理中→完成／失败／取消；不重复发起，不自动重试；输出与请求身份绑定，离开页面清除对话与秘密 |
| 调用记录 | 网关真实处理生成调用时产生请求标识和元数据；管理员从调用结果进入记录核对 | 处理中→真实终态；历史分页可查，实际用量来自上游，缺失值为未知；不存完整对话或凭据 |

能力边界：产品负责配置、授权、代理、控制台反馈和安全元数据诊断；供应商负责生成与实际用量；运行环境由本机运营者维护；Agent Platform 负责编排及 Connector 回执，不成为产品内置业务依赖。统一体验由管理员闭环承担，应用访问和供应商授权仍各有责任边界。

异常与人工介入：地址／凭据错误返回表单反馈和修正入口；依赖缺失或停用引导配置／启用；上游失败展示中文原因类别、请求 ID 与记录入口，管理员决定修正后显式再次调用；网络未到达网关或存储无法记账提示记录不可用，不能伪造成功或诊断行。存储 degraded 沿用停止服务、排查磁盘／权限后重启的正式规程。退出和页面切换停止当前测试并隔离旧结果，不自动恢复生成。

## 5. 范围与优先级

下述 US-01～08 均为 P0，构成完整切片。现有实现不是范围限制：为满足计数、真实状态、同请求定位等可做必要的最小后端增强，但保持唯一上游及现有外部协议；本节点不预决 API、表结构或组件。可评审原创交互原型或等价设计由 design 节点完成，不能把本轮归为 CSS 改动。

质量与规模边界为现有团队自用单实例，桌面验证采用既有 1280px 与 390px 窄屏，覆盖鼠标与键盘操作；不承诺无证据的吞吐、可用率或响应时间目标。已有超时、体积限制、来源校验、登录限速、凭据加密／摘要与无重试约束持续有效。

第 2–4 项均为已授权持续目标，顺序依赖和新 Issue 接续责任见公共路线，不以重新证明多供应商／治理／部署需求或用户再次发起为条件；只有成员角色和额外协议扩展按实际场景选择。发现阻断当前首次调用的需求缺口回到本基线修订，不把后续项目提前放入本 Run。

## 6. User Story、业务规则与 Acceptance Criteria

所有验收由研发提供自动回归和项目测试真实回执，独立 QA 审核覆盖及证据；项目维护者据此决定最终交付。以下 AC 是可观察结果，不是实现任务。编号是本 Run 专属，与历史 AC 不混用。

### US-01 进入和恢复任务上下文（G1、G4）

作为管理员，在打开或重新访问控制台时，我能知道当前任务并回到目标页面；会话无效时正常重新登录。

- AC-01：概览、上游、模型、密钥、测试与记录有明确导航、当前页语义、任务标题和说明。直接进入／刷新每个目标页面和返回／前进均恢复正确页面；未知目标安全回到有效入口，不造成空白或泄露内容。只有非敏感页面标识进入导航地址。
- AC-02：会话过期在管理读取／写入中均显示中文原因与重新登录路径；清除秘密及输出，不把应用密钥的 401 当管理员会话过期。重新登录恢复非敏感目标页面，测试不自动再发。已有密码显隐、失焦／登录后隐藏与清除行为保持。
- AC-03：1280px 和 390px 无阻断主任务的横向溢出、遮挡；表格可在自身容器滚动。键盘可完成登录、导航、表单、复制、原始诊断展开、取消及记录核对，焦点可见，当前页和异步状态可被辅助技术感知。

### US-02 理解真实网关状态和下一步（G1、G2）

作为管理员，在空配置或已有配置时，我能区分保存与可用性，并知道下一步。

- AC-04：概览从真实服务展示运行版本、上游已配置／启用状态、模型及应用密钥数量；数量是已保存对象总数且启用数量另有清晰口径。已知空列表才显示 0；读取失败或未知显示未知／加载／失败，不能用 0、演示记录、图表或健康填空。healthz 版本原值包括 `dev`，失败／缺失／空值／5 秒超时显示“版本未知”，不阻塞管理。
- AC-05：接入步骤可进入对应任务；未配置、已保存待调用核验、已有实际成功调用证据可区分。保存永不等于验证成功，未实测不显示供应商成功。成功证据展示可核对请求和适用配置；变更配置后不把旧请求成功冒充当前配置成功，历史成功可保留但明确历史含义。无可靠证据时保持待核验，不为了标记完成自动调用供应商。

### US-03 从空配置准备访问（G1、G2）

作为管理员，在初次登录且业务配置为空时，我通过 UI 建立一个有用的上游、别名及应用密钥，并能纠正失败。

- AC-06：真实 Go 服务从空配置全程 UI 完成上游地址／凭据保存与启用→模型别名创建→应用密钥签发→普通及 SSE 调用→记录核对。每个缺失依赖有明确说明和对应页入口，不用 API／SQL 预填、手改库或创建无业务作用对象绕过步骤。
- AC-07：上游未配置／保存／停用状态清楚；同地址留空凭据保持旧值，地址变更须输入新凭据，服务端秘密不回显；模型和密钥区分空状态、加载失败及真实列表，具备创建、已有启停和模型映射编辑动作。取消创建／编辑不发写请求，失败／取消保留必要非敏感输入及原对象；留在页面修正无需重建对象。保密清除规则优先于保留敏感值。

### US-04 安全取得和使用调用权限（G1、G3）

作为管理员，我能一次取得新密钥并将其安全用于客户端或测试，遗失后有恢复办法。

- AC-08：完整应用密钥仅签发当次展示；关闭展示、跳页、刷新／退出后不可再从 UI 或列表取得完整值，后续只见名称、安全标识及启停状态；遗失提示重新签发并停用旧值。不得把密钥放入 URL、localStorage／其他持久浏览器存储、日志、截图或报告。复制是管理员显式动作，不自动读取或清空系统剪贴板；提示其保密责任。上游凭据与管理员密码同样不持久化在浏览器。
- AC-09：界面给出当前网关 Base URL（含正确协议入口）及可复制客户端示例；示例使用应用密钥占位符与公共别名／明确的模型占位符，不嵌入真实凭据，也不把供应商地址误作网关地址。复制失败提供中文反馈与可手动选择的示例，不触发调用。新密钥若用于测试，只通过明确用户动作进入当前页面内存或由用户输入，不能从密钥摘要恢复。

### US-05 执行可理解的普通与流式调用（G1、G2、G3）

作为管理员，在已有启用别名和合法应用密钥时，我能明确发起、观察和终止一次调用。

- AC-10：测试选择真实已启用别名；无可用模型时解释依赖并引导模型／上游页。清楚呈现输入、待发送、处理中、完成、失败／不完整、取消状态；普通默认展示可读文本，SSE 在上游结束前逐段可见；可按需展开本次原始响应诊断。无文本而有合法工具结果时给出可理解摘要和诊断入口，不伪造文本；非法／中断结果不标完成。
- AC-11：请求处理中重复点击／按回车只产生一次生成 POST；取消中止客户端和受控上游，取消后状态不会被迟到成功／失败改写。开始输出后取消或失败不自动重发。缺少 SSE 结束标记、流中错误与网络断开显示失败／不完整；正常结束才完成。取消不能保证供应商撤销费用，界面明确告知。
- AC-12：旧请求的成功、错误、增量和收尾均不得污染后来请求、其他页面或重新登录会话。跳页、退出及会话失效清除密钥、上游凭据、测试消息、可读／原始输出，停止请求；取消沿用现有敏感清除边界，失败后仍在本页可修正非敏感选择，未经用户动作不再请求。诊断输出按文本处理，不执行 HTML，不从上游错误提取／回显秘密。

### US-06 找回同一请求的诊断（G2、G3）

作为管理员，在调用完成或失败后，我能进入记录并核对这一次，而不是猜测最新一行。

- AC-13：结果提供来自网关的请求标识和记录入口；在记录页通过精确请求身份定位／突出对应记录，存在更新或分页时仍可找到，不仅按时间猜测。成功、上游失败、模型拒绝及可识别的停用密钥拒绝均核对模型、密钥安全标识、状态、延迟、实际／未知用量；未知项明确为未知，真实 0 可显示 0，历史记录不被覆盖。
- AC-14：网关已受理且可落盘的生成请求，无论完成或失败，均能从请求 ID 关联真实记录；无法识别密钥的拒绝不捏造归属，记录仅存允许的安全元数据，管理员鉴权后才能查看。请求未到达网关、尚未拿到请求 ID、存储不可用或取消尚未落终态时，显示准确的不可用／待记录状态和手动刷新／排查路径，不制造行、不以另一请求顶替、不以请求 ID 当成功凭证。记录和服务日志不保存完整提示词、完成内容或秘密。

### US-07 从错误中恢复（G1、G2、G3）

作为管理员，在配置或调用失败时，我能理解原因类别并通过受支持操作恢复，不必解释内部英文码。

- AC-15：错误地址、缺失凭据、无模型／模型停用、密钥停用／无效、上游停用／失败、流中断、网络及存储故障均显示中文说明与适当修正入口或操作；表单错误定位可理解，不仅显示内部英文码。未知码提供安全通用说明及可得请求 ID。后台状态码、错误结构和原有代理协议兼容，UI 不透传敏感供应商错误；应用拒绝不访问上游。
- AC-16：修正地址／凭据、启用上游／别名、重新输入或签发可用密钥后，可显式重新发起独立新请求并核对新记录；取消恢复操作不产生写入／生成，失败不会被成功提示掩盖；无自动付费请求、自动重试或绕过安全校验。
