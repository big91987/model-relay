## 3. 方案与简化审查

主/支持专业模块已完整读取：后端与分布式系统、安全架构；另读专家路由、架构分析视角、评审/产物契约。按小应用裁剪为一份架构、一份等价交互与本评审，无组织运营文档、额外领域ID、组件平台、长期成功验证实体或新ADR。不是多Agent或独立专家评审。

否决仅前端拼现有列表：真实总数和拒绝记录无证据，无法满足AC。推荐原生前端+最小Go管理只读聚合/精确ID查询、会话到期元数据及拒绝安全记账；维持现有存储。配置代次仅在进程内抑制迟到成功，引用持久request ID且查询真实终态；重启显示待核验，以可解释的保守行为换取零迁移成本。所有配置成功写入均撤回旧证明（包括增加密钥），是刻意保守的显示范围，不影响历史记录。

每个保留机制有当期责任：hash解决导航；全量COUNT解决截断计数；精确ID查询解决分页关联；进程代次解决配置并发/旧成功；会话/页面/调用身份解决乱序；有界缓冲解决长流内存；拒绝元数据解决安全失败追踪。删除这些会丢当前AC，除此之外不预建路由/治理抽象。新增读取仍需管理员鉴权，内部识别停用密钥不授予调用权限。

## 4. 风险、验证与下游责任

非阻塞风险及退出门槛：

- 真实供应商凭据未提供：只验证明确受控夹具，不消耗付费额度；供应商联调标未测，不影响进入研发，但不能称产品全量通过。
- 存储失败不能保证记录存在：保持fail-closed和准确“可能不可记录”，测试Start/Finish错误；若仍产生成功/假行则AC失败。
- 拒绝日志增加写入面：沿用请求/超时限额，专项并发/磁盘失败测试；拒绝后上游POST必须为0；高负载容量无测量，不承诺SLA。
- 配置变更、普通写失败、SSE收尾可能更改终态：候选需校验持久success，race/迟到/重启回归不通过则不能显示当前成功。
- 静态browser.check不验证Go接口，本阶段不调用它伪造运行验收。沙箱监听受限时使用固定host-only项目Connector，保留限制而非扩权。

研发交付必须覆盖三个文档及18条AC，维护真实`.trellis/spec`并扩展可信`make verify`，不重写历史门禁、不API/SQL预填首次业务配置。证据与QA报告保存本Run根，失败记录保留。先专项前端/HTTP测试，再固定验证入口；项目测试与独立QA按真实回执核对。报告节点在本Run的pr.md写对外PR正文；本节点不创建PR/分支/提交/推送/合并/部署。
