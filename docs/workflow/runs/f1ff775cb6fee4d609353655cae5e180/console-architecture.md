# 首次调用闭环：架构与实现契约

状态：Draft / 推荐执行，G2 设计自审见 [g2-review.md](g2-review.md)。依据为 [本轮 PRD](product-definition.md)、[G1](g1-review.md)、[公开行为观察](reference-observations.md)及现有 Go 实现。用户已授权普通选择自动推荐并继续；本设计不是用户逐项批准、实现完成或独立 QA 结果。2026-10-06，代码基线 `d62cd51e8de2127548e1ac7469d349443d1bfe3d`。

## 1. 总体影响与范围

目标：管理员在同一控制台完成空配置→接入→授权→普通/SSE 调用→同请求核对，并能理解和纠正失败。团队管理员兼任运营者，负责供应商授权、费用、容量和存储故障处置；应用调用方只有应用密钥权限；供应商提供生成与可得用量；项目维护者承担后续 QA、测试仓合并、正式测试部署与体验核验。运营和公共后续路线唯一以 [产品委托](../../../product-brief.md)与 [路线图](../../../roadmap.md)为准，不复制路线。

当前实现仍是一个 Go 进程、单管理员、SQLite、唯一上游、原生 HTML/CSS/JS。本轮修改控制台状态和必要管理查询/拒绝记账，不改 `/v1/models`、`/v1/chat/completions` 外部生成协议，不引入业务队列或外部服务。可评审原创交互以 [完整交互设计](console-interaction.md)的逐页线框、状态表、焦点和场景代替静态演示；它不冒充浏览器验收。

主要交付影响：研发需同步扩展前端异步所有权、管理查询、生成拒绝记录与真实浏览器旅程；不能仅改 CSS。安装、备份、启动入口继续使用 README；无新存储表、无版本迁移、无新权限。后续多上游和治理不属于本 Run。

## 2. 能力、领域与事实源

派生数据：概览计数来自 SQL 聚合，不由截断为 1000 条的列表长度推导；“当前配置曾成功”只引用真实持久请求，不成为第二事实源。前端草稿、加载状态和当前请求身份均是短生命周期内存，不写持久浏览器存储。供应商模型名称不是新增领域 ID。

## 3. 流程、信任与故障边界

```text
管理员浏览器 -- 管理Cookie + Origin/CSRF --> Go管理API -- 受控写入 --> SQLite
      |                                  |-- 只读安全聚合/精确记录 --> 控制台
      +-- 显式应用Bearer --> Go代理 -- 服务端加密凭据解密 --> 唯一供应商
                                 |-- Start/Finish安全元数据 --> SQLite
                                 +-- X-Request-ID + JSON/SSE --> 当前测试页面
```

管理成功只承诺配置保存，不能推导供应商可用。生成在可落盘 Start 后才访问上游；Finish 失败保持现有 degraded/fail-closed，不向调用方报告已确认成功。普通响应正文及 SSE 只存在本次页面内存。SSE 已发响应头后不能重写 HTTP 状态，仍使用现有 `event: error`，不改协议。

管理导航、健康版本和各查询独立进行；healthz 失败不注销会话。管理 API 401 才清会话；生成 401 只代表应用凭据拒绝。管理服务与代理共用进程和 SQLite，故障域相同：不承诺控制面宕机后数据面继续工作。存储无法记账则不启动新的供应商调用；已输出后失败保留真实不完整状态，不能撤销费用。

## 4. 最小接口增强

以下均为推荐新增的管理只读能力，不是基线已存在接口。新处理继续经过 `admin` 的会话校验；不新增公开诊断接口。

### 4.1 GET `/admin/api/overview`

返回无秘密的配置快照：`upstream: {configured, enabled, credential_configured, revision}`、`models: {total, enabled}`、`keys: {total, enabled}`、`call_evidence: null | {request_id, time, alias, model, key_id, upstream_revision, scope}`。`scope` 固定为“本次服务启动、当前配置的一次已记录成功”。概览版本仍独立取 `/healthz.version` 原值，不从此接口重新定义版本。

配置快照的 SQL 查询在一个只读事务内执行，管理锁保证其不与配置写入穿插；计数来自全量 COUNT/启用条件聚合。查询出错返回原 503 storage_unavailable 协议，UI 把相关卡片标为未知并给重试入口，不提供虚构默认 0。上游没有行是 configured=false 的已知空，不等于查询失败。

成功证据采用进程内保守指针，不新增持久业务对象：Server 内持有配置代次和至多一个候选请求 ID；启动为空。每次成功上游保存、模型创建/编辑/启停、密钥签发/启停，持管理锁提升代次并清候选，即使是同值保存也重新核验。失败写入和取消不提升代次。生成取得有效配置时在同一读锁下捕获代次和现有上游 revision；不把秘密纳入公开指纹。

Finish(success) 确认落盘后，只有捕获代次仍为当前代次才登记候选 ID。概览返回候选前必须精确读取该记录，确认 state=success、上游/别名/密钥仍启用且映射吻合；若候选随后被 Finish 改为 canceled，清候选，不报告成功。登记和清理必须在生成释放读锁后短暂获取管理锁，不能递归加锁；候选失效只清自身，不能覆盖另一请求的新证据。数据读取失败为未知，不能当无成功。

这是“当前启动下当前配置曾成功一次”，不是持续健康、所有模型可用或供应商认证。之后有失败不会抹掉“曾成功”事实，但结果仍显示当次失败。浏览器刷新/重登录可重新读取该证据；服务重启后显示“已保存；本次启动尚无当前配置成功证据，可查看历史记录”，不把老记录当新配置成功。记录历史不删除。代次只负责防止配置变化与迟到成功混淆，不暴露新对象 ID，不更改 requests.revision 的既有含义。

### 4.2 GET `/admin/api/requests/{id}`

精确主键查询，返回现有 Record JSON（usage/duration/upstream_status 保持 null 语义），无正文、token、URL或额外秘密。合法 ID 不存在返回 404 not_found；无会话 401；存储查询失败 503；不支持其他方法。对长度/字符做有限校验，不接受 SQL 片段，使用参数化 SQL。

列表 `/admin/api/requests?cursor=...&limit=...` 保持既有分页。记录页独立展示定位结果和分页列表，定位行不被分页覆盖；根据 ID 去重，不把最新行当目标。接口只查真实行；未找到暂不能区分响应先到/最终未记录，因此 UI 明示“暂未找到”，提供手动刷新，不伪造终态。后端不通过此查询重放请求。

### 4.3 现有会话响应的兼容补充

POST login和GET session在既有csrf等字段之外增加`expires_at`（服务端现有Expiry的UTC RFC3339值），只给有效管理员，不暴露会话Cookie。前端取得后安排保守本地到期清除；服务端认证仍是权威，不延长既有8小时期限。浏览器时钟变化/休眠恢复重新检查session，检查401立即清理；定时检查负责发现服务重启或会话撤销。旧客户端忽略新增字段，外部生成协议不变。该字段为本轮研发新增，不能假定基线已提供。

## 5. 安全拒绝的最小记账

基线 generate 在第一次或第二次 appID 失败时直接返回 401，无记录；这是本轮必须修复的事实缺口。引入只供内部使用的凭据识别查询，能够辨认已存在但 disabled 的摘要，授权仍要求 enabled=true；`/v1/models` 授权不放宽。对外无效与停用密钥继续统一 401 unauthorized，不能通过响应暴露密钥是否存在。

处理顺序：服务端生成 ID→检查存储状态→识别/授权→必要的受限元数据解析→持久拒绝或捕获有效配置→Start→至多一次转发→Finish。所有可落盘的生成拒绝（包括缺失/未知密钥）均 Start/Finish 为 rejected，保存 ID/时间/安全 error_code/耗时。未知密钥 KeyID 为空，不能由请求输入或前缀猜归属；无需读取其正文，别名/模型/流标记未知。可识别的停用密钥只在已有 1MiB/10秒读取上限内解析请求：仅保存通过现有 alias 校验的公开别名、可核对的映射和 stream；不验证成功也不向上游发送；非法或过大正文仍返回原 unauthorized，别名未知。第二次授权拒绝也记录同一 ID，不为竞争停用开旁路。

记录不得存 Authorization、原始请求体、请求者传入的任意错误文本、上游错误正文。允许的安全字段沿用现有 schema；不能为使诊断完整而放宽鉴权/请求限制。正常授权后的模型拒绝记录 public alias；没有可核对映射时真实模型未知。无效/停用密钥及模型拒绝必须断言上游 POST 为零。

存储已 degraded，或 Start/Finish 失败：原 fail-closed 流程优先，允许返回 storage_unavailable，UI 显示“请求记录可能不可用；停止重试并按运行说明排查存储”，即使有 ID 也不保证有行。不得回落到内存伪日志冒充持久记录。拒绝记录会增加磁盘写入面：保持现有请求体上限、读/总超时与按请求有界写入，测试并发拒绝与写失败；单实例没有容量/SLA 承诺。未知密钥攻击可能使记录增长，运营者监控磁盘并使用受控网络部署；不在本切片自造配额/限流体系或默默丢掉应记录请求。

## 6. 前端异步所有权与生成状态机

统一所有权：会话代次 sessionEpoch、页面代次 navigationEpoch、每次操作唯一内存对象。每个 fetch/JSON读取/剪贴板等待/stream.read/错误处理/finally 写 DOM 前都确认三者仍匹配；取消只终止传输，不替代身份隔离。旧请求即使忽略 abort 也不能写入新页面、当前通知、密钥展示、取消按钮或新会话。

页面切换、退出、过期、pagehide 同步提升代次、停止当前测试、清秘密/消息/正文/原始诊断/一次签发值，之后才开始新页读取。只保留允许的非敏感页目标、选中别名和（同一次会话内）请求 ID 的内存定位信息；退出/过期再清定位信息。跳页不把密钥隐式带到测试页，选用手动粘贴或输入方案。数据库记录当然不被清除。

调用状态：ready→waiting_headers→receiving→complete / failed / canceled；failed 包括“不完整”。提交事件首先同步建立 activeCall 并禁用发送，然后才 await；回车和按钮都经过同一忙检查。一个忙请求最多一个生成 POST。取消先标记 canceled/失效，清密钥、消息和输出，再 abort；保留已收到的非敏感 ID 与“取消不保证撤销费用”的提示。开始下一次请求前增加调用身份，旧 finally 不解锁新请求。

读取 response.headers 的 X-Request-ID（错误时兼容 JSON request_id）；该 ID 来自网关，不解析上游 JSON id 作为网关身份。没有 ID 时显示“未取得网关请求标识，无法定位”，不能自行生成假 ID。普通 JSON 以 choices 中的文本为默认视图；合法工具结果以工具名/数量摘要加诊断入口呈现。SSE 正确处理多段 UTF-8、跨块 CRLF、多行 data、event:error、usage 与 [DONE]；有错误/非法 JSON/未结束标记不完整，不因 EOF 就完成。局部工具增量不逐段展示为假文本，结束后给摘要。原始响应保留在当前页的有界内存，按文本显示；不要用 innerHTML。解析或诊断大小达到现有协议边界时显示截断/失败实情，不声称完整；不增加超出基线的产品协议承诺。

页面可读输出和原始诊断各最多保留256Ki字符（独立上限）；超限停止累积相应显示文本并明确“显示已截断”，继续有界解析SSE以判断真实终止，不因此重发或把传输失败标为完成。工具摘要只保留计数和有限名称；底层普通响应/单事件大小仍按现有Go限额。传输完成与显示截断是两种属性，完成文案注明截断，原始入口不得承诺完整原文。离开/取消仍清全部缓冲，确定性测试覆盖长流内存不持续增长。

管理会话检查：进入测试前验证 session，测试完成/取消后刷新诊断需要管理会话；测试页空闲时下一次管理操作发现401也清除。生成期间额外每30秒只检查 session（仅测试页可见且有敏感字段/输出时；不轮询healthz），page visibility 恢复立即检查；到已知过期边界或管理401立即取消并清理。网络检查失败显示“管理会话暂无法确认”，安全清理敏感内容、保持非敏感目标，不误称401；重新登录/检查由用户触发。测试请求的应用401不触发全局登出。轮询和计时器均受页面/会话身份限制，退出清除。此策略用于发现本页长流中的过期，不改服务端会话寿命或认证模型。

## 7. 质量场景、安全与容量

| 场景/不变量 | 可测门槛与责任 |
|---|---|
| 无秘密跨生命周期 | 签发关闭、跳页、刷新、退出、过期及取消后 DOM/内存所有权失效；URL及浏览器持久存储无秘密；测试证据先清除秘密才截图；研发+QA |
| 非文本及恶意诊断 | HTML样式输出只显示文本；不执行工具调用；不透传敏感上游错误；从受控恶意响应核验；研发 |
| 迟到/并发/重试 | 一次提交仅一次POST；取消被上游观察到；忽略abort的旧JSON/增量/错误/finally均不得改新状态；配置变更中旧成功不成为当前证据；研发 |
| 首次使用与可访问性 | 1280px/390px全程键盘完成，焦点明确、异步状态可感知、表格局部滚动；健康5秒超时不阻塞；QA |

## 8. 方案比较、推荐与退出路径

目标模块是控制台首次使用和安全诊断；负责状态呈现、配置调用闭环、精确查询，不负责调度、商业计量、安装平台或供应商探活。必需接口为现有管理/生成协议，质量重点是秘密生命周期、请求所有权和真实证据。

| 方向 | 覆盖、代价与退出 |
|---|---|
| 仅前端拼接现有列表 | 改动小，但列表1000上限无法证明总数，拒绝无记录、历史分页关联不稳定；不能满足AC，Rejected |
| 原生前端+最小Go查询/拒绝增强 | 覆盖当前切片，无新服务/表；运行期成功证据重启后保守失效；推荐 Draft，按授权继续；可独立回退UI/API变更而不迁移数据 |
| 新框架/持久配置版本和验证实体 | 可长期保留更细成功证据，但增加构建/迁移/身份成本；当前无必须跨启动保留核验标记的需求，后置，不预建 |

推荐选择现有原生页面，hash页面路由，新增两个管理员只读接口和安全拒绝记录。原生方案可逐步提取纯函数，不要求组件框架；Go Handler/Store 分工沿用项目风格。成功证明保守失效是明确代价，不是健康缓存。没有难以逆转的新决策，故不另造 ADR；已接受约束保持Accepted，新增建议保持Draft而不是伪称用户批准。

唯一接缝是既有上游revision、alias、key ID和request ID；进程配置代次不是持久产品对象。后续多上游、密钥治理、升级回退按公共路线独立Issue依赖前切片接续，届时需要跨启动可核验证据再引入持久版本。本轮回退不删/改数据库；新增拒绝行仍可由旧分页接口阅读；旧二进制缺新API，旧UI与旧API必须同版本部署。

## 9. 实施与验证交接

按纵向顺序实施：Go聚合/精确查询及拒绝元数据→控制台导航/概览/依赖→模型编辑/密钥一次展示→普通/SSE及中文诊断→真Go浏览器首次UI闭环与专项回归。允许研发在同一小应用内组织任务，不拆多服务，不重建项目级PRD或覆盖历史工作流设计。

研发维护 `.trellis/spec` 的真实前后端规范（prepare显示未初始化），内容依据本设计和实际实现，使用挂载研发Skill规定入口；不在设计阶段伪造初始化回执。固定入口是 `make verify`，不得绕开或重写可信门禁。真实Go浏览器由该入口启动服务和明确夹具，初始化仅管理员通过正式命令，上游/模型/应用密钥一律UI操作。新增前端确定性测试覆盖忽略abort与迟到结果；Go HTTP/race测试覆盖安全拒绝、聚合超过1000和精确查询权限/分页/故障。

设计阶段只做契约、追踪、文档检查，未运行make verify。研发、项目测试和独立QA必须保留真实命令/代码标识/退出码、失败和后续重跑，证据置本Run根。既有密码显隐/healthz/历史日志保护/HTTP/SSE/持久化继续回归。无真实供应商凭据即供应商联调未测；无回执即不宣称PR、合并、部署及部署后体验通过。

## 10. 证据与专家综合

主专家按后端与分布式系统模块进行本节点内分析：问题是状态所有权、并发配置成功证据、拒绝记账和精确查询；事实来自 server.go/proxy.go/store.go 的锁、schema、拒绝顺序和记录生命周期，置信度高。建议不引入队列/迁移，通过同进程代次与持久记录组合隔离迟到成功；验证条件是race/配置变更/终态修正，失败则不展示当前成功。不决定供应商可用性与未来多路由。

支持专家按安全架构模块进行本节点内分析：只审查秘密生命周期、主体隔离及拒绝归属；事实为独立admin会话、app_keys摘要、加密上游和元数据表。建议内部识别与授权分离，但外部401不区分、不增加访问权；验证未知/停用密钥零上游、未知归属、日志/截图无秘密，不能验证则该AC未通过。不决定新角色、合规或企业IAM。

总体综合：保持持久requests为诊断事实源，用保守运行期指针而非数据库迁移证明当前配置；以明确未知降低误报，不降低鉴权/失败追踪承诺。未知是实际供应商响应与拒绝写入在真实负载下的成本，前者留未测，后者由隔离并发测试与运营监控验证。没有方向级需求缺口，无需退requirements；没有独立专家Agent或独立QA审签，本节是本节点专业视角自审。
