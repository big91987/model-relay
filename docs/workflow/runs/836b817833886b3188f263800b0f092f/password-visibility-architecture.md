# 登录密码可见性：增量架构与实现契约

Run：836b817833886b3188f263800b0f092f；需求事实源：[product-definition.md](product-definition.md)，G1：[g1-review.md](g1-review.md)。本方案只覆盖 Issue #12；现有项目级 brief、roadmap、v0.1 范围和历史设计继续有效，不复制或覆盖。

## 1. 目标架构

### 目标、角色与能力边界

管理员在同一次输入中主动核对密码，随后正常登录并使用管理台；返回登录页始终隐藏且清空。管理员兼任本机凭据保管和运营责任人。研发负责局部实现、Trellis 与验证，独立 QA 负责证据核验，平台负责阶段调度、Issue 和 Git 发布。成功标准为需求 AC01—AC13 的本轮证据，不以设计就绪代替验收。

| 能力／领域 | 所有者及事实源 | 受支持路径与边界 |
| --- | --- | --- |
| 输入核对／登录页面 | 管理 UI；当前输入节点的 value、type | 输入、原生按钮切换、登录态转换时清理；只在当前 DOM 生命周期有效 |
| 管理员认证／会话 | 既有 Go 服务与会话机制 | 沿用 login、session、logout；页面可见性不参与鉴权 |
| 凭据运维 | 管理员及现有 Go 命令 | README 的 init、reset-password --password-stdin；本轮不变更摘要、权限或数据 |
| 管理／代理及交付验证 | 既有 Go 产品、验证入口和平台 | 管理操作、健康与版本回归保持；make verify 与独立 QA 为交付门槛 |

运行拓扑沿用 Go 服务提供原生 HTML/CSS/JS。应用与供应商不参与此切换路径。非目标包括其他凭据输入显示、记住密码／显示偏好、认证协议变更、多用户、部署和真实供应商调用。

### 流程、状态与权威写入

只用 password 节点的 type 作为可见性事实源，不保存第二份密码或持久化状态。单个局部更新函数同步 type、按钮文字和状态说明，单个重置路径恢复隐藏。所有新增 DOM 写入由管理页 JS 负责。

| 起点／事件 | 结果 | 值与失败契约 |
| --- | --- | --- |
| 首次载入或未登录刷新 | type=password；显示密码；密码已隐藏 | 初始空值；HTML 本身即定义隐藏默认态 |
| 隐藏态点击／Enter／Space | type=text；隐藏密码；密码已显示 | 原节点、原 value 不变，不提交或校验，不调用网络 |
| 显示态再次激活 | type=password；显示密码；密码已隐藏 | 原 value 不变，保持按钮焦点 |
| 主动登录成功／有效会话恢复 | 隐藏并清空输入，进入管理台 | signedIn 保留既有清空并加入隐藏重置 |
| signedOut：退出成功或认证失效 | 隐藏、清空，显示登录页 | clearSecrets 清空并重置可见性；signedOut 继续沿用该入口 |
| 登录拒绝 | 既有错误提示，可重试 | 当前 api 的 401 调用 signedOut，因此清空且隐藏；不增加“保留错误密码”逻辑。其他错误沿用原处理，不伪造成功 |
| 退出失败 | 沿用当前错误路径 | 不绕过服务端响应伪称成功；401 仍走现有 signedOut |

输入的 Enter 保持原先主动登录语义；只有切换按钮聚焦时的 Enter 是切换。切换期间不重建输入或表单，不读取密码来生成展示说明、日志或消息。不使用异步任务、请求身份、计时器或新增控制面对象。

### 可访问与视觉契约

- 新增原生 button，明确 type=button，ID 建议 password-toggle；独立于密码 label 的内容，保留输入现有 ID 与管理员密码标签关系，可将标签改为显式 for=password。
- 按钮文字直接提供可访问名称：隐藏时「显示密码」，显示时「隐藏密码」。不设置固定且与可见文字矛盾的 aria-label。
- 按钮 aria-controls=password，aria-describedby 指向 password-visibility-status；状态说明显示「密码已隐藏」／「密码已显示」，使用 role=status、aria-live=polite。说明只包含状态，不包含输入内容。
- 采用动态动作名称的普通按钮模式，不混用 aria-pressed 的稳定名称 toggle 模式。Tab 顺序为密码输入、切换、登录；原生 Enter／Space 激活，事件只用 click，不手工叠加 keydown 导致双切换。
- 沿用 focus-visible 样式。按钮在输入下方、登录按钮之前，状态说明另行显示；不采用绝对定位覆盖输入。切换和登录按钮之间有间距，390px／1280px 操作可达、无横向溢出，点击目标至少沿用现有按钮尺寸。样式调整仅限登录区。

## 2. 方案比较与决策

目标模块为管理员登录页面，负责输入可见性与同步反馈，不负责身份或凭据存储；必需接口为原生输入、按钮和既有登录生命周期。质量要求是保值、零提交、可访问反馈和秘密清理。

| 方案 | 覆盖、代价和成立条件 | 可逆性与验证 |
| --- | --- | --- |
| A：原节点切换 type，动态动作按钮＋状态说明 | 满足用户文案与当前布局；仅少量 DOM 变更，名称和说明须同步 | 推荐；按矩阵验证，可局部回退，无数据迁移 |
| B：固定名称＋aria-pressed | 两态语义明确；固定名称与需求推荐的显示／隐藏动作文字不一致，需重新定义视觉文案 | 可行但不采用；同样需要实际可访问检查 |
| C：框架组件／复制输入／偏好存储 | 增加依赖或秘密副本、焦点与同步负担，持久化偏好违反本轮边界 | 不采用；无当前需求支持这些新增责任 |

决策状态：A 按用户明确委托的普通选择自动推荐采用（Accepted，委托范围内；非另一次逐项批准）。独立 QA／用户业务验收尚未发生。低影响、可逆、无公共协议变化，不触发独立 ADR 门槛。回退可撤销新增 UI／局部 JS，不影响会话或持久数据；回退意味着本轮功能未交付，不把它算作验收通过。

简化审查：保留一个原密码输入、一个按钮、一个状态说明和同步／重置函数；删除重复密码变量、额外布尔事实源、框架、接口、存储、遥测和扩展点。可信近期变化只有登录输入核对，不建立泛化秘密显示组件；未来用户明确要求其他凭据可见性时重新评估边界。

## 3. 安全审查（主专家模块的本地应用）

问题边界是输入核对过程的数据保护；不改变 IAM、授权或供应商安全。依据为当前 HTML／app.js、PRD AC05—AC09 与已完整读取的安全专家手册。代码事实置信度高，新增浏览器及辅助技术行为须研发验证。

资产为管理员输入、既有会话及验证证据；主体为管理员、同机旁观者、浏览器、Go 服务和验证人员。输入在 DOM 内，只有主动 login 走既有网络认证边界；切换与状态说明完全在浏览器内。服务端认证摘要／会话仍是权威认证事实，可见性不授予任何管理权限。

| 威胁路径 | 风险及控制 | 发现／隔离／恢复责任 |
| --- | --- | --- |
| 主动显示后旁观者看到屏幕 | 中：显式主动显示、清楚状态与隐藏操作，成功登录／退出重置 | 管理员管理屏幕风险；研发验证重置；必要时隐藏／退出 |
| 按钮默认 submit 造成无意认证 | 中：type=button，原生 click，无网络／form 调用 | 请求计数和提交计数测试捕获；研发修正；QA 阻止交付 |
| DOM 状态漂移或跨登录态残留明文 | 中：单一 type 事实源、同步反馈、清理时统一重置 | 单元／真实旅程核验；返回隐藏空态恢复 |
| 复制密码进存储、消息、URL 或测试证据 | 高：无密码副本、无新增记录、测试不输出输入值／请求正文 | 代码与存储检查；QA 发现即停止交付并清理泄露证据，真实泄露按现有凭据轮换规程处理 |

租户与网络控制沿用单管理员／现有来源校验和会话机制；无新租户、权限、密钥、外部依赖或供应链组件。审计只记录命令结果、路径、状态与代码标识，不新增密码切换遥测。测试截图不得含显示中的密码（包括合法隔离凭据）；断言失败不得打印实际秘密值，关闭 trace／HAR 或过滤秘密，不把错误正文和环境变量整体导出。

设备、扩展和密码管理器不由产品控制；autocomplete=off 是现有属性而非“不可能被浏览器记住”的证明。不声称完全清除浏览器内存或符合某合规认证。没有新增法规适用性输入，此增量无合规结论。安全专家不决定业务角色／最终验收；总体结论为无需新增后端控制或扩大验证权限，显示有固有旁观风险且已限定在用户主动动作。

## 4. 实施与验证契约

研发先读取本轮需求和本文，完整执行其 Trellis Skill 与 references：若 .trellis/spec 仍为空模板，依据现有 Go／原生前端／浏览器测试原位 bootstrap，再实际 before-dev、check 并记录。阶段 Skill 记录放本 Run；.trellis 的规范、任务与工具运行目录仍遵循自身约定，不启动第二套调度器。

修改范围建议：internal/relay/web/index.html、app.js，必要的 style.css 登录区样式；tests/browser/ui.test.mjs、journey.mjs。不改 Go 认证、健康、运行版本实现、数据库或验证入口。VM fixture 应支持新增节点 type／属性；桩测试不能证明原生键盘、必填校验或真实可访问语义。

| AC | 研发验证和独立 QA 取证 |
| --- | --- |
| 01—02 | 单元＋真实浏览器检查初态、重新载入、空值、含空格／特殊字符的隔离输入，多次切换后原值一致；断言输出只报布尔结果 |
| 03—04 | 真实 Tab、Enter、Space 旅程，按钮保持焦点、焦点样式；名称、描述、status 文本和 type 一致，检查可访问树／语义，不冒称屏幕阅读器音频验证 |
| 05 | session 初始化已稳定后取请求基线；鼠标／键盘、空／非空输入切换期间所有请求增量为零，表单 submit／invalid 事件为零。仅统计路径／次数，绝不记录请求正文 |
| 06 | 用真实 Go 服务分别在显示／隐藏态成功登录；错误凭据真实拒绝，再输入可登录；成功后输入清空并隐藏；不靠拦截伪造成功 |
| 07—08 | 显示态登录后退出，再输入仍隐藏；有效会话 reload 恢复；真实 logout 使会话失效后刷新回隐藏空态，并用单元测试覆盖管理请求 401 的 signedOut |
| 09 | 静态检查无新增秘密存储／日志；未登录切换前后 URL 与浏览器存储不变，登录／退出后无输入残留。会话 cookie 沿用现有断言，不要求合法认证后全部 cookie 不变 |
| 10—11 | 保留 390px／1280px 管理旅程；现有健康 GET／HEAD／拒绝方法／异常状态测试、版本原值／未知／重试／迟到响应隔离及真实健康一致性旅程继续运行 |
| 12—13 | 当前 make verify 完整结果＋代码标识；保留失败和沙箱限制，必要时固定 host-only Connector；独立 QA 逐项核对并复核历史哈希、git diff 与产物路径 |

make verify 的现有顺序为 evidence、health-history、format-check、go mod verify、vet、frontend-test、race/HTTP test、build、真实 Go browser journey；不缩减、替换或补造受信门禁。隔离临时目录／随机端口、受控测试上游不是真实供应商验证。静态 browser.check 不属于本轮后端验收；不制作原型或 PoC，现有页面与此明确状态契约已足够实施。

进入研发条件：G1 已就绪、契约和状态边界无冲突。进入 QA 条件：实际代码、Trellis 动作记录和当前验证回执齐备，未通过则明确失败／限制。退出条件为独立 QA 审核 AC01—AC13；最后由平台发布 PR，用户决定合并。本设计节点没有执行产品测试或独立 QA。

## 5. 风险、未知与证据依据

无阻塞需求缺口。剩余执行风险为遗漏 signedIn／clearSecrets 重置、动态名称与状态不同步、键盘测试只模拟 click、测试输出秘密；上述矩阵为验证与停止条件。若真实浏览器发现不能保值或既有认证生命周期与需求冲突，先定位实现问题；确需改变需求时沿平台 requirements 路由返回，不静默弱化 AC。

本轮事实依据：internal/relay/web/index.html 的登录表单；app.js 的 api、clearSecrets、signedIn、signedOut、form、logout 与 session 恢复；style.css 的焦点／窄屏规则；Makefile；tests/browser 的 VM fixture 与真实 Go 旅程。docs/workflow/design.md 仅恢复既有版本功能边界，为历史证据，不是本轮方案或验证结果。

官方机制参考（本轮读取 W3C 页面，2026-10-06）：W3C APG Button Pattern，https://www.w3.org/WAI/ARIA/apg/patterns/button/ 。其按钮动作名／描述、Enter／Space、保留上下文时保留焦点，以及动态名称按钮与稳定名称 aria-pressed 模式的区别，支撑本文可访问契约；未读取任何其他中转产品实现。
