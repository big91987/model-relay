# 管理员登录密码可见性：广义 PRD

Run：836b817833886b3188f263800b0f092f；来源：平台送达的 Issue #12 用户任务与 intake 交接。本文为本轮增量需求基线，评审见 [G1](g1-review.md)。

## 1. 背景、问题与证据

团队管理员在登录前需要核对已输入的密码，减少无法发现输入错误带来的反复输入。现有登录页仅提供隐藏密码输入与登录操作；目前只能重新输入并尝试登录。用户明确要求增加可逆的显示／隐藏能力；没有密码错误频率、节约时间或采用率数据，不设虚构量化收益目标。

项目方向沿用 `docs/product-brief.md`、`docs/roadmap.md` 和 `docs/releases/v0.1.0.md` 的团队自用、单管理员模型中转服务。本轮仅改善进入既有管理台的认证旅程，不重新建设首版产品。旧 `docs/workflow/task.md`、`requirements.md` 及 Issue #8/#9 交付、QA、日志均为历史资料，不能作为本轮完成证据。

## 2. 产品目标、成功标准与非目标

一句话目标：管理员能在主动核对密码后恢复隐藏并正常登录，且密码不会因核对操作被提交、记录或持久化。

成功标准：本轮全部 P0 验收条件获得当前实现与真实验证证据；固定 `make verify` 结果经独立 QA 核验；平台更新原 Issue 并由 Connector 交付 PR。需求就绪、历史测试通过和草稿 PR 均不等于本轮功能验收或发布。

非目标：更改管理员认证、密码策略、重置规程或会话协议；增加上游凭据／应用密钥显示功能；自动记住密码或可见性偏好；新增权限、账户、供应商接入或其他路线图能力；部署、真实供应商调用、付费操作及自动合并。

## 3. 用户、运营模式与责任

| 角色 | 工作与责任 |
| --- | --- |
| 团队管理员／运营者 | 使用既有凭据进入管理台、主动核对输入、退出会话；负责本机访问权限、凭据保管、安装和支持处理 |
| 用户委托方 | 决定产品范围、业务验收与最终合并；已授权普通产品和技术选择自动推荐推进 |
| 研发阶段 | 实现真实行为，按要求执行 Trellis，补回归并提交固定验证入口的真实结果 |
| 独立 QA 阶段 | 核验新增行为、既有功能回归、文档保留和证据来源；记录失败与环境限制 |
| 平台 Connector／Hook | 阶段调度、原 Issue 回写、Git 发布及 PR 交付 |

运营方式为既有单管理员自用服务。管理员兼任本轮凭据风险与支持责任人；规模与容量保持现有产品边界，本轮不新增预算、服务承诺或运营组织。应用调用方和上游供应商不参与此认证改善闭环，也不提供验收依赖。

## 4. 产品级业务架构、对象与生命周期

端到端价值流：管理员取得可用凭据 → 打开登录页 → 输入隐藏密码 → 按需显示核对／重新隐藏 → 主动登录 → 使用既有管理台 → 退出 → 返回隐藏且密码已清空的登录页。

| 核心对象 | 首次可用、核验、变更与退出 |
| --- | --- |
| 管理员凭据 | 运营者通过 README 规定的 Go `init` 命令在空安装创建，终端仅展示一次并由运营者安全保管；通过管理网页登录核验。忘记／变更密码时按 README 的停服与 `reset-password --password-stdin` 正式规程操作，重启后新密码可登录，旧凭据与旧会话失效；本轮不改变此规程，不以改数据库代替入口 |
| 本次密码输入及可见性 | 管理员在登录页输入；初始隐藏，主动切换仅改变显示状态并保留值；成功登录、会话恢复进入管理台或退出回登录页时遵守既有秘密清理边界，返回登录页重置隐藏；不跨页面加载保存 |
| 管理会话 | 既有登录成功后建立，页面刷新按既有会话恢复规则进入管理台；退出或会话失效回到登录页，保留既有认证与访问隔离规则 |

产品能力边界：登录输入核对由本产品提供；初始化、凭据变更与后台管理由现有产品入口提供；研发编排、Git 发布与验收回写由平台负责；供应商协议与费用不在本轮闭环。

异常流程：错误密码仍按现有登录结果提示并允许重试，切换不会绕过校验或制造成功；会话失效后回到隐藏登录态；退出失败遵循既有错误处理，不伪称退出成功。忘记密码由运营者经正式重置入口介入，不通过扩大权限或测试数据库直改解决。

## 5. 阶段范围与业务规则

所有下列需求均为 P0，形成“核对输入—登录—退出”的独立可验收薄切片。桌面和既有窄屏旅程都能操作；交互可逆、无需外部服务、无需新增持久化数据。

- G1 核对便利：默认隐藏，显示／隐藏可重复切换，保留输入的完整内容。
- G2 可访问与安全：鼠标和键盘均可操作，名称和状态清楚，切换只影响可见性，不执行登录或产生额外网络提交。
- G3 生命周期与回归：退出后隐藏且清空；既有登录、会话恢复、认证失效处理、管理操作、健康方法契约和运行版本展示不回归。
- G4 可审计交付：隔离验证、独立 QA、真实结果、旧文档保留与正确的 Run 产物位置。

低风险推荐默认（非用户逐项确认事实）：隐藏时可见操作文案为「显示密码」，显示时为「隐藏密码」；辅助技术同时能判定当前状态和操作目的；焦点在键盘切换后保持可继续操作，避免无故跳走。具体语义编码、布局与实现由下游设计确定。

后置项：其他敏感输入的可见性、自定义显示偏好、复杂密码管理、多用户认证。只有用户新需求改变输入范围、凭据安全边界或运营模式时重新定义，不作为本轮验收前置条件。

## 6. User Story 与验收标准

验收责任：研发提供测试与固定入口回执，独立 QA 对全部 AC 逐项核验，委托方负责最终业务验收。下表是预期行为与验证方式，不是已经执行的结果。

| Story／目标 | 前置、动作与业务结果 | P0 AC 与验证方式 |
| --- | --- | --- |
| US1／G1：管理员核对输入 | 未登录，输入密码后反复显示／隐藏，确认输入并保持原值 | AC01：首次显示登录页和重新加载的未登录页均隐藏；AC02：含空格及特殊字符的隔离测试输入反复切换后值完全一致，空输入也可切换且仍为空。验证初态、值一致性及真实浏览器可见／隐藏结果 |
| US2／G2：仅用键盘核对 | 未登录，经顺序键盘导航到切换控件，激活并再次切回 | AC03：Tab 可到达、焦点可见，Enter 与 Space 均可激活并保持可操作焦点；AC04：每次切换后可访问名称、当前状态与实际显示一致，无歧义的显示／隐藏用途；不只以颜色或图标表达。验证真实键盘旅程及可访问属性／浏览器语义 |
| US3／G2：核对不触发认证 | 未登录，密码为空或有值，使用鼠标和键盘切换 | AC05：任何切换都不提交登录表单、不触发必填提交校验、不产生认证或其他网络请求；登录请求计数不变。验证表单提交与网络观察，隔离测试不得记录密码请求正文 |
| US4／G3：核对后正常登录与重试 | 有合法凭据，按需核对后主动登录；另以错误测试凭据主动登录 | AC06：显示态与隐藏态均能用原值正常登录并清空秘密输入，进入真实管理台；错误密码仍失败、提示可理解且可继续输入／切换／重试，无自动提交或认证绕过。沿用真实 Go 服务认证旅程并补失败覆盖 |
| US5／G3：退出与恢复 | 登录成功后退出；另验证有效会话刷新与会话失效 | AC07：退出成功回到登录页时密码为空、隐藏，名称／状态恢复初态，重新输入不会继承上次显示状态；AC08：有效会话恢复进入管理台，不泄露旧输入；会话失效回登录页同样隐藏且清空。验证退出、恢复及失效旅程 |
| US6／G2、G3：秘密留在当前输入生命周期 | 输入并切换，再登录／退出／重新加载 | AC09：产品不将密码或可见性偏好写入浏览器持久／会话存储、URL、日志、遥测或新增后端记录；除主动既有登录认证外不发送密码。代码检查结合隔离浏览器存储／请求检查；截图、日志、回执不含秘密。服务器现有认证摘要不在“禁止新存储”范围内 |
| US7／G3：继续管理 | 登录或恢复会话后使用既有管理台 | AC10：现有管理台旅程不回归，桌面与窄屏新增操作可达且不阻挡输入或登录；AC11：健康接口已有 GET／HEAD、拒绝方法及异常状态契约继续通过；运行版本原值、未知降级、重试及迟到请求隔离仍通过。使用现有自动回归与固定入口，不将历史成功当作本轮结果 |

## 7. 依赖、风险、假设与开放问题

已确认决策：用户当前任务为最高优先级增量范围；普通推荐直接推进；固定验证入口为 `make verify`；不部署、不调用真实供应商；Git 和 Issue 操作由平台负责。

依赖：现有 Go 服务认证／会话与正式运维入口；现有真实服务浏览器测试；项目固定验证 Connector；独立 QA。研发须完整读取其适用 Skill 和 references，按现有 Go、原生前端、浏览器测试完成空白 Trellis 规范的适用补齐，再实际执行 before-dev 与 check，并记录真实动作；这些是后续执行责任，不是本阶段完成事实。

风险：显示状态可能泄露给旁观者，只有用户主动显示；切换名称与状态不一致会误导辅助技术；意外提交可能增加登录失败或触发限速；返回登录页残留显示状态或密码可能跨会话泄露。AC02—AC09 约束这些风险。用户设备自身的输入法、浏览器扩展或密码管理器行为不由产品承诺控制；产品不主动记录或保存秘密。

假设：沿用现有管理员账号和管理台，不扩大权限或浏览器支持范围；视觉细节可由设计阶段安全调整。没有改变产品方向或妨碍验收的未知项，无须新增访谈。若后续证据发现认证生命周期冲突，反馈本需求基线而非静默改变安全规则。
