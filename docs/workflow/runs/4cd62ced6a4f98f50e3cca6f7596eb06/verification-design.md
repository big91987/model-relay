# 验证设计、验收映射与证据门槛

architecture-r1；2026-10-07；完整正式标准入口仍是原材料 `docs/acceptance.md`，实际根/SHA见 [architecture.md](architecture.md)；当前矩阵见 [acceptance-matrix.md](acceptance-matrix.md)。本文定义必须实现的测试，不将设计计划改为Pass。

## 1. 固定入口与证据契约

唯一产品门禁为 **`make verify`**。保留现有格式检查、锁定模块校验、go vet、frontend-test、`go test -race -count=1`、构建及真实Go服务浏览器入口；扩展覆盖新身份/资源/分账/迁移，不移除已有安全、取消、路由、健康及版本可信测试。现有health-history gate是历史版本回归，不是本轮AC证明，不能用它代替新增测试。若旧测试契约需随新产品变更，保留变更依据及新正反例，不把失败断言直接删掉或放宽。

浏览器测试运行实际Go后台、SQLite及独立受控HTTP/SSE上游，由Go测试runner拥有临时目录、随机端口和进程退出/清理；Node/Playwright仅测试依赖。测试不读用户配置、不访问真实供应商/用户数据，不手改数据库制造通过。旧版本fixture可通过旧版公开init/UI/API或项目拥有的显式测试fixture构造，但必须记录schema/版本/固定摘要和来源，不能伪称读取真实供应商资料。

设计静态工具browser.check只能证明原型，不能证明后台；本阶段没有运行它，因为已有原型授权且无需重建。研发/项目测试Connector在宿主执行完整固定入口；Agent沙箱监听失败单列，不能用沙箱限制代替业务失败/成功，也不要求广泛提权。独立QA在同一材料摘要/工作树指纹上独立读回回执、逐项操作，并保存缺陷返研及复验。

每次证据保存本Run根下 `validation/<attempt>/`，保留失败、不覆盖旧attempt。目录名由实际执行生成，handoff列实际路径。记录命令、开始/结束、exit、材料version/archive SHA、HEAD、tracked diff摘要、未跟踪产品文件清单及SHA、测试工具版本、构建version、UI视口、服务schema和受控上游边界。缓存/runtime secrets放忽略目录，提交的日志、截图/视频/JSON只有脱敏内容。截图遮秘密，一次展示也不得存真实值；自动断言可验证secret存在/摘要不可逆且证据只记录布尔结论。

逐项状态用Pass / Fail / Not Run / Blocked及证据路径、限制、缺陷与重验版本；没有日志/日志截断不能推断通过。固定入口exit0不证明所有AC已覆盖，QA还检查测试名/断言/页面动作和版本一致。真实供应商、外部支付/身份单独Not Run；完整退出的H事实必须由对应平台证据闭合，不因产品测试pass自动勾全。

## 3. 不变量与故障注入最小集合

- 并发准入：tenant和Key都剩1时让不同Key/两代秘密竞争，断言只有合法名额dispatch，其他记录零dispatch，两个scope无部分扣计。独立把C、count、RPM、TPM、费用设0/null/1及修改低于已用，验证不清零。
- 有界预留：三个候选不同四费率，预算恰好足够全尝试上界与少1微美元分别成功/拒绝；支持字段、缺输出上限、非法n、无可信上界都真实验证。上游超声明上界不裁账，停止保护候选并展示违约风险。
- 用量完整性：失败已知、超时未知、成功已知组成一个请求；逐项输入/输出null与0不同；SSE无最终usage、仅total、重复相同累计、迟到较大累计、不同证据重复量、较小累计、错误价证据均有断言。
- 崩溃点：受理提交前/后、attempt可能dispatch提交后网络前、网络成功账本前、取消与finish竞争、核对commit后响应丢失、close与更正竞争；测试进程kill/restart及安全API读回，不只调用内存恢复函数。
- 时间边界：秘密expires/grace截止前/等/后、UTC月末/分钟末、回拨后重启；旧窗口未决预留carry可用量不增加、确认归原周期。时间为测试注入而非系统改时钟。
- 迁移失败：只读校验不能先改started，备份失败原库无差异，schema1→3中途失败整个rollback，错误key/破坏包不写新目录；回退不能丢弃新费用而声称无损。
- 读取安全：跨租户ID/查询/游标/导出、开发者未分配Key、成员退出/降权后旧session、迟到UI响应/退出敏感清除；检查返回内容而非只检查菜单隐藏。

实际用量/费用优先通过正式管理API和UI观察；测试可只读SQLite确认秘密不落盘及ledger守恒，禁止改生产/fixture数据库记录让断言通过。受控收据必须明确来源“test-upstream”，不得将其写成供应商事实。

## 4. 浏览器完整旅程

每个视口1280/1440/390运行同一关键结果：真实登录→服务接入失败草稿恢复→核验→发布/价格→建两租户及接受邀请→租户真实登录→建Key/诊断分配→普通及SSE→同ID日志→轮换/收窄授权拒绝→预算修正/暂停恢复→账单核对/关闭拒绝和合法关闭/更正→筛选页2/导出→退出清敏感/重新登录。至少一套完整键盘路径验证导航、弹层focus trap、Escape返回、错误定位、secret清除；390操作不能被样式隐藏。

测试账单历史时间由Go测试时钟/可控正式调用形成，核对/关闭通过真实API/UI；不在浏览器放固定演示金额或SQL改日期。多对象数据来自正式入口，非默认生产seed。页面对照逐页记录信息层级、主要动作、抽屉/编辑、异常状态，允许实现细节变化但不得删冻结结果。

## 5. 研发顺序与退出

1. 先schema3/用户资格/正式安装升级与安全scope，完成邀请→Key→调用的真实纵向链，旧密码/Key及安全回归同时跑。
2. 原子资源/有界策略/多尝试快照/追加双费用和核对，同步补竞态、丢响应和重启测试。
3. 账单关闭/更正、真实统计/分页/导出、十页A工作台，补全J01–J07和三视口/键盘，不能把后端工作推给静态原型。
4. 扩展且运行固定make verify，记录完整回执/失败及修复版本；提交独立QA使用的实际路径和矩阵。内部迭代不需要重复要求用户批准进入阶段。

研发退出条件：上述每项已有真实实现和对应测试，固定入口真实回执、工作树指纹与材料SHA一致，已知失败如实列缺陷，供应商等外部Not Run边界明确；独立QA与发布尚属后续职责。设计退出仅为机制/入口/故障/测试契约完整，不把未来成功预写。
