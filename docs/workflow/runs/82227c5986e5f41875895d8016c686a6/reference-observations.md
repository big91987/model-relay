## 推荐选择与理由（非用户逐项新批准）

用户已明确自动推荐，本节点据此采用下列可验证产品边界，具体实现交设计：

- 大数优先与正权重：中文“优先级”一致，启停不混入权重0。默认0／1，有限整数范围使错误输入可观测。
- 同级平滑加权轮转：相比随机抽样，小团队可用连续请求计数稳定证明权重真实生效；不以统计运气判断通过。周期变化和重启边界显式，不保证并发完成顺序。
- 有限顺序切换：3次总尝试而非3次追加重试，同一上游只一次；仅明确暂时类别切换，协议／请求错误不盲目重放。保留整体300秒与已有头／流空闲时间，加60秒输出前尝试约束避免单次普通响应耗尽所有机会；仍不宣称供应商SLA。
- 冷却30秒与用户请求恢复：简单、可重复验证；不新增后台生成费用或外部基础设施。未知可参与，手动停用永不自动解除，旧配置迟到结果不得刷新新健康。
- 连接核验访问模型列表：明确“连接”与“生成”差异；非生成也不能保证免费，不绕费用授权。若供应商不支持列表，显示失败／限制，不将其自动永久禁用。
- 用量已知部分＋未知：保留重复生成和费用风险，不推估供应商账单或提前实现路线3计价治理。
- 停用退出、备份回退：保持历史身份，当前无需硬删除。旧二进制直接开新库不作承诺，恢复升级前完整备份是明确支持边界；升级后新增数据不隐式保留。
- 文档裁剪：单一Run PRD与G1满足小应用需求契约；公开参考与决策独立保存以免PRD充满方案辩论。无方向性未知，不重复审批、不先编码、不新增不适用平台文档。
