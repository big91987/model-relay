# 多上游、有限故障切换与可解释控制台：需求基线

状态：Ready for Architecture。2026-10-06，依据用户自动推荐并持续推进的明确授权完成 [G1 评审](g1-review.md)；不表示实现、固定门禁或独立 QA 通过。

## 1. 背景、问题与证据

来源：Issue #18 原始用户委托及入口交接；精确基线 main `85f6d17c07c5fddeb2d6a39a5a067769a11bb4cc`。产品方向见 [产品委托](../../../product-brief.md)，唯一公共阶段及发布事实见 [路线图](../../../roadmap.md)，首版回归见 [基础契约](../../../releases/v0.1.0.md)。上一切片 [PRD](../f1ff775cb6fee4d609353655cae5e180/product-definition.md)、[架构](../f1ff775cb6fee4d609353655cae5e180/console-architecture.md)、[交互](../f1ff775cb6fee4d609353655cae5e180/console-interaction.md)、[QA 快照](../f1ff775cb6fee4d609353655cae5e180/acceptance/report-02.md)作为回归输入；唯一上游和不跨渠道切换的阶段限定由本轮规则取代，其余安全与用户生命周期约束保持。

现状：生成与概览仍读取唯一上游，公共别名仅对应一个远端模型，管理员不能通过备用供应商维持公共模型服务，也无法解释多次尝试。用户提供的双屏测试观察指出概览长信息混排、完成步骤长期占位、账户动作与业务导航同权、技术说明占用产品页面。当前替代方案是人工改唯一上游及映射，再由应用重新发请求；故障期间影响连续使用且增加重复费用与诊断成本。暂无故障频率、团队规模或提效百分比实测，不虚构运营指标。

已确认事实：用户报告第 1 项已合并并正式测试部署；本节点核对本地 HEAD 与精确基线一致。上一 QA 的发布未执行结论保留为历史快照。当前请求整体时间默认 300 秒、SSE 空闲默认 60 秒及响应头默认 30 秒为已有代码事实。公开资料观察及本产品决策分别记录于 [参考与决策](reference-observations.md)，不是现有实现能力证明。

## 2. 产品判断、目标及当前切片

一句话判断：团队管理员运营多个上游与稳定公共模型名，应用在明确的时间、费用风险和停止边界内获得路由结果，管理员从同一请求解释去向、失败及恢复。

| 目标 | 可观察成功标准 | 阶段优先级 |
|---|---|---|
| G-A 稳定接入 | 从正式 UI 建立两个独立上游和一个多候选公共模型；普通及 SSE 真正访问各自远端模型 | P0 |
| G-B 有界可靠性 | 优先级、权重、禁用、冷却、有限切换及恢复均以真实外部请求计数与结果验证，输出／取消后不重放 | P0 |
| G-C 可解释运营 | 同 Request ID 逐尝试、安全原因、时间与未知／部分用量可查；保存／连接核验／生成成功有独立语义 | P0 |
| G-D 连续可用 | 桌面、390px、键盘完成管理→调用→故障诊断→恢复；上一 main 真实数据升级不丢对象或历史 | P0 |

本轮为公共路线第 2 项的一个完整纵向切片。全部下述 Story／AC 为 P0；没有以 P1 名义隐藏的必需闭环。单管理员、单实例、小规模团队自管；至少两个上游，没有硬编码两条限制，不承诺未经测试的容量或可用性 SLA。达到规模或运营责任变化时由维护者依据实际采用重评公共路线。

非目标：路线第 3 项权限／有效期／轮换／配额／业务限流治理，路线第 4 项全套安装升级平台和新协议；多管理员、多租户、计价结算、商业售卖、复杂指标与图表、外部调度器、分布式设施、后台付费生成探活、同一请求并行竞速或工具执行。现有初始化、备份恢复、协议、安全限额持续回归；本轮数据变化所需升级与回退边界属于当前交付责任。

## 4. 产品级业务架构与对象生命周期

价值流：登录并识别待办→接入多个上游→显式连接核验→发布公共模型候选→签发／使用应用密钥→显式普通或 SSE 调用→按规则选择及有限切换→同请求诊断→修正／等待冷却恢复→停用退出。

能力边界：网关拥有接入配置、公共模型映射、调用授权、选择规则、有限切换和安全诊断；供应商拥有实际生成与账单；应用拥有收到终态后的新调用决策。统一公共名不承诺不同供应商输出质量相同、不同远端模型功能完全一致或 exactly-once 执行。

| 对象 | 来源、首次可用与正式入口 | 变更、退出与不变量 |
|---|---|---|
| 管理身份 | 运营者通过已有 init／serve 建立并登录 | 正式退出／会话过期清秘密；应用密钥不可管理 |
| 上游 | 管理员取得授权凭据，通过 UI 新建名称、地址及凭据并启用；保存后为未核验 | UI 编辑／启停；凭据不回显，同地址留空保留原值，变更地址须新凭据；禁用不删除历史，不强行终止已开始尝试 |
| 连接核验证据 | 管理员在目标上游 UI 显式发起连接核验 | 附时间和适用配置；改地址／凭据后旧证据仅历史；不能证明任意模型生成可用 |
| 公共模型及候选 | 管理员 UI 创建公共名，关联已保存上游和各自远端模型，定义候选启用／优先级／权重 | 编辑后新请求使用新配置；取消不写；公共名保持稳定，现有别名不可隐式改名；本轮通过停用退出，保留历史，不强制引入硬删除 |
| 应用密钥 | 管理员 UI 签发，一次性展示并安全交应用；调用测试显式输入／使用 | 正式启停；遗失重新签发并停旧密钥；摘要不可还原，浏览器不持久存储完整值 |
| 调用与尝试 | 应用或管理员显式发起，网关产生单一 Request ID；实际访问供应商才形成尝试 | 终态后不可自动重发；同 ID 保留真实时间、配置适用范围和安全结果，历史不可覆盖或虚构 |
| 候选暂时健康 | 当前候选配置的实际生成结果产生，初始未知 | 失败冷却、到期可再尝试、成功恢复；手动禁用独立；重启清暂时健康为未知，历史失败可查 |

异常闭环：无配置→就近进入接入／映射；核验失败→修正供应商配置；调用可切换故障→有限后续尝试；全部不可用→稳定终态与手动排查；流中失败／取消→停止且记录不完整；存储失败→停止新增生成并告知证据不可得；会话过期→清秘密、重新登录回到安全任务页，不恢复发送。

## 5. 可观察业务规则

以下是本产品本轮采用的推荐契约，数值为有界行为决定，不是性能测量或供应商 SLA。具体持久化、接口与并发实现交设计。

### R-1 上游与核验状态

每个上游具有独立身份及名称、地址、凭据已配置／未配置、手动启停；名称非空且可区分，名称重名拒绝，编辑名称不改变身份。列表和详情同时能看见配置状态与核验证据，不能将启用或保存涂成“连接成功”。

连接核验仅显式执行非生成的模型列表访问，不发送聊天生成，不跟随重定向，受既有地址和凭据安全规则约束，单次上限 10 秒，失败不自动重复。不因浏览器加载、保存、重启或冷却到期而自动请求供应商。操作旁说明“只检查连接与模型列表；不发起生成，供应商可能对接口访问收费；不保证目标模型能生成”。重复点击不启动并发核验；取消或会话离开停止该操作。

核验状态：未核验＝当前配置未执行；核验中＝本次正在访问；成功＝合法模型列表响应；失败＝已知网络／超时／鉴权／限流／协议错误；未知＝结果未取到、读状态失败或尚无可靠终态。结果带完成时间和适用配置；旧成功不可充当当前成功。核验失败不改手动启停，不改生成候选冷却；核验成功也不替代生成成功。生成成功只由实际正常完成请求证明，具体候选和配置范围可查。

### R-2 候选、优先级与同级分配

一个公共模型可关联多个独立上游，每个上游在该公共模型中最多一个候选；候选指定远端模型名、启用状态、优先级及权重。公共名沿用现有合法性规则；空远端模型、重复上游候选、不存在的上游引用和非法整数不能保存。优先级为 0–100 的整数，默认 0；**数值越大越优先**。权重为 1–100 的整数，默认 1，只在相同优先级有效；停用用启停表达，不以权重 0 代替。

先过滤公共模型停用、候选停用、上游停用／凭据缺失、当前冷却及本请求已尝试上游，再选最高优先级；同级采用确定性平滑加权轮转，稳定候选集合下按权重分配，不承诺一次调用或并发完成顺序的比例。平局按稳定候选身份排序，配置／可参与候选集合变化或重启重新开始周期。状态未知且配置完整的启用候选可以参加，未知不显示为健康。只有高优先级候选全部被过滤／已尝试后，低优先级才有机会，权重不能压过优先级。

验证口径：稳定的两个同级候选权重 1:3、无其他流量、连续 40 次成功非流式请求，实际接收数应为 10:30；1:1 连续 20 次应为 10:10。优先级 10 与 0 且均可参与时，连续 10 次全部到优先级 10；禁用高优先级或令其冷却后才访问另一候选。分配按实际尝试发起顺序观测，不由配置 JSON 推断。

新请求使用受理时的完整路由配置范围；运行中编辑不混合新旧映射。管理员保存停用成功后，不再开始该对象的新尝试，包括已受理请求后续尚未开始的切换；正在执行的尝试允许完成，取消仍优先。配置停用不伪装成供应商故障。

### R-3 故障切换、总次数及时间

顺序尝试，不并行竞速；一次网关调用总计最多 **3 次尝试（含首次）**，同一上游最多一次。两个候选都失败只访问两次，不能补第三次重试；更多候选也不超过三次。尝试只计实际发起供应商生成的访问；被过滤候选不计付费尝试。接入、鉴权、请求合法性和存储可记录性检查在访问供应商前完成。

| 失败／终止类别 | 客户端尚未收到响应时可切换 | 健康影响及业务结果 |
|---|---|---|
| 连接建立／TLS／网络传输错误、尝试超时 | 是，剩余预算内换未试上游 | 当前候选冷却；可能已执行，不能声称无费用 |
| HTTP 408、429、500、502、503、504 | 是，剩余预算内换未试上游 | 当前候选冷却；本轮不在同请求等待 Retry-After 后重发 |
| 其他 HTTP 4xx（含 400/401/403/404）、其他 5xx、重定向 | 否 | 安全拒绝／失败，建议修正或手动禁用；不触发暂时冷却，不推测永久健康 |
| 非法 JSON、错误内容类型、无效 SSE 协议／工具结果结构 | 否 | 安全协议错误；不重放，不触发本轮暂时冷却 |
| 客户端取消、总体 deadline、管理鉴权／调用鉴权／模型拒绝、存储失败 | 否 | 停止，不开始另一生成；取消和本地故障不计供应商冷却 |
| 已向客户端提交响应头或任何正文／SSE／工具增量后的任意错误 | 否 | 终态失败／不完整；若原因是上列暂时供应商故障，可冷却以影响未来新请求 |

整体时间沿用默认 **300 秒**，从网关受理开始覆盖验证、所有尝试、传输及流结束，不按切换重置；更短的已有配置／客户端 deadline 优先。每次获取响应头沿用默认 **30 秒**，SSE 空闲沿用默认 **60 秒**；新增每次尝试在对客户端提交响应之前至多 **60 秒**，普通完整结果或 SSE 首次可提交响应均受此限制。开始输出后仍受整体及流空闲上限。测试可通过隔离配置／可控时钟缩短等待验证同一规则，必须另核对生产默认值；取消后不得继续启动切换，正在执行的上游收到中止。时间上限不是允许跨越冷却等待的理由。

无有效候选：503、现有 `upstream_unavailable` 语义，零生成访问；明确无配置、停用、冷却或凭据缺失原因。实际尝试全部失败／次数耗尽：502 与稳定的“尝试已耗尽”安全错误类别；整体预算耗尽：504，超时；客户端取消沿用取消记录，不能伪造客户端收到的成功／错误。单次不可切换错误保持现有 HTTP／安全错误结构。设计明确新增机器可读错误码，Request ID 及已支持协议不变。SSE 头已提交后保持既有流内错误方式及不完整终态，不将 HTTP 200 单独当成功。

操作旁说明有限切换可能产生多次供应商调用和费用；网络失败也可能已执行，网关不保证供应商 exactly-once 或取消撤费。用户显式“重新调用”产生新 Request ID，不能复用旧 ID 隐藏重复生成。

### R-4 暂时健康及恢复

健康按公共模型的具体候选及当前配置区分，避免一个远端模型失败无依据封禁该上游全部模型。一次 R-3 暂时故障使该候选从故障完成时间起冷却 **30 秒**；未到期不得参加新尝试，全部冷却也不绕过。到期变为“待重新尝试”，允许下一次有资格的新用户请求参与；没有后台生成探活。重试成功恢复最近成功状态，再失败重新冷却 30 秒，不无限延长旧失败，也不永久封死。高优先级到期后按正常优先级重新参与。其他不可切换错误展示最近失败并提供修正入口，不产生未约定的自动永久禁用。

手动停用永不因冷却到期、核验成功、生成旧结果或重启自动启用；冷却计时不可解释为运营停用。地址／凭据／远端模型变化使对应证据失效并将暂时健康置未知，不能接受旧配置迟到结果为新配置健康；只改名称／优先级／权重／启停不清除未到期冷却，防止启停绕过。重启允许暂时状态置未知、调度周期重置，持久配置、手动停用及历史不变，UI 明示运行适用范围，不宣称持续已健康。

### R-5 同请求诊断、用量及证据安全

一个 Request ID 包含实际尝试顺序、上游安全身份／名称、公共与远端模型、配置适用范围、开始／结束时间、耗时、结果、安全原因与可得用量；还可解释候选被停用／冷却／低优先级过滤。最终使用上游只有实际正常完成时才标成功；失败仍展示最后尝试但不可标“成功上游”。零尝试拒绝、暂时处理中、最终成功／失败／超时／取消／流不完整可区分。

每次尝试分别保存供应商实际返回的 prompt／completion／total tokens，缺失保持未知，0 只表示供应商真实返回 0。所有尝试该项都已知才可标完整总量；部分未知时仅显示“已知部分合计＋若干尝试未知”，全部未知显示未知，不能拿最后成功用量作全部消耗；供应商失败响应不从敏感错误正文挖掘用量。只有已经解析出的合法成功协议用量可记账，不能据此推算币种／价格／账单。历史单上游记录未含尝试明细时标“历史记录无逐尝试证据”，不补造尝试或替换原用量。

仍精确定位同 ID，跨分页／刷新／重新登录可以显式查询；找不到、存储故障和终态尚未落盘分别提示。无法开始落盘则 fail-closed，零供应商访问；收尾写失败不得标已确认成功，不自动切换／重发，明确记录不可用。记录、日志、概览及截图不保存凭据、提示词、回答、原始供应商敏感错误或堆栈；管理诊断只供管理员。普通／SSE 原始成功输出仅遵循现有调用测试页面的临时诊断与清密规则，不写到持久调用记录。

### R-6 控制台与连续任务

概览用短业务状态与下一步组织，显示真实保存总数与启用数，未知／读取失败不当 0；完整 Request ID、可读时间与原时间、配置适用范围、运行范围在详情可查。当前生成成功只能指向具体候选和适用配置，不把一次成功概括为所有上游健康。当前步骤只突出未完成任务，已完成步骤可回看，不重复编号；没有可靠当前成功证据仍明确待核验，不自动花费生成补证据。

业务导航与账户／会话恢复／退出分组；正常使用突出上游、模型、调用与记录任务；会话故障在就近位置提供恢复。工程栈、内部门禁和研发术语留工程文档，费用提醒及能力限制贴近核验、路由配置和调用操作。状态使用中文及文字，不仅颜色；两屏任务入口可发现，键盘焦点可见、顺序合理、错误就近可修正。

上游与模型列表→详情→编辑→保存／取消→核验／调用→记录→修正不依赖 API 或 SQL。取消编辑不发写入；失败保留非敏感草稿并定位错误，敏感值按既有规则清除；保存成功而刷新失败要区分，恢复只读，不再保存／生成。保持旧请求隔离、重复发送锁、一次性密钥、导航清密、过期清密与重新登录、不将应用 401 当管理登出。

### R-7 旧数据升级与回退

上一 main 真实运行的安装经正式入口升级，原唯一上游成为可运营上游，原每个别名成为指向原远端模型的单候选公共模型，初始优先级 0／权重 1，原启停不变；凭据仍可解密、原应用密钥仍可调用、身份与历史时间／状态／用量不变。原上游没有名称时赋可编辑且可区分的迁移名称，不虚构核验成功。升级可重复启动，不能再次新增重复对象，不删除重建数据库，不把初始化当迁移。

升级前由运营者停止旧服务并通过支持入口备份数据与解密所需材料，备份含秘密且不进仓库。失败保持备份可恢复，不能启动半迁移服务；版本不支持时清楚拒绝。**不承诺旧二进制能直接读取升级后的库**；回退采用停止新服务、恢复升级前完整备份、启动精确旧基线的隔离验证，明确升级后新增配置／密钥／请求不包含在旧备份内，不静默丢弃或混并。实际执行用户环境破坏性恢复须另获授权，验收在临时副本完成。

## 8. 依赖、风险、假设及设计待解问题

已确认：本轮进入路线2，Go后端、单管理员／实例、原创实现、普通选择自动推荐、后续路线3/4独立Issue；不读取本机New API；发布责任按节点划分，用户既有授权持续有效。

本轮推荐并采用的产品决定：大数优先、正整数同级权重及平滑加权轮转、最多3个不同上游顺序尝试、错误白名单、30秒候选冷却及被动恢复、模型列表非生成核验、保留300/30/60秒既有整体／头／流空闲并新增60秒输出前尝试上限、停用而非硬删除、备份恢复型回退。理由与未选方案放参考／G1，不在本文充当实现设计。

依赖与风险：
- 真实供应商凭据、兼容模型、预算由管理员提供；当前未提供，真实供应商Not Run。模型列表核验不保证生成或费用为零，失败重放可能重复计费，必须就近提示。
- 当前唯一上游、别名和概览不足以支撑规则；需要迁移与事实源扩展，架构必须解决加密关联及旧记录没有尝试事实，不能伪造补齐。
- 并发配置、取消、健康迟到及存储收尾失败可能污染诊断；设计必须明确新尝试开始边界、旧配置隔离及fail-closed，测试覆盖竞态。
- 默认整体上限保持，但60秒输出前尝试界限是新增行为；长时间无结果调用可能更早终止，需用户操作提示及专项验证，不将限制说成供应商 SLA。
- 现有测试环境Go/C及浏览器依赖须通过正式路径可用；缺依赖或平台回执故障回维护源，不能修改平台DB、造回执或以另入口取代make verify。
- 实际团队容量、更多供应商和跨浏览器采用尚无量化；当前不设置未经证据的吞吐、费用节约或高可用承诺。
