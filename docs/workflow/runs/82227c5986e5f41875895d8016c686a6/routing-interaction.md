# 多上游运营与诊断交互契约

2026-10-06，设计就绪，尚未进行本轮真实浏览器验收。本文件为原创任务线框、状态及键盘契约，不是已运行原型。来源为 [PRD](product-definition.md) US-01～10及 [架构](routing-architecture.md)。上一 [交互](../f1ff775cb6fee4d609353655cae5e180/console-interaction.md) 的密码显隐、一次性密钥、可读普通/SSE/工具输出、精准Request ID、会话/导航隔离继续有效；多候选页面和下述概览分组取代原唯一上游相关呈现。

## 1. 信息架构、布局和导航

```text
Model Relay                         账户 [会话与退出 ▾]
业务导航：概览 / 上游 / 公共模型 / 应用密钥 / 调用测试 / 调用记录
main：页面标题 → 本任务状态/下一步 → 主要动作 → 列表/详情/编辑
就近异常：原因 → 可执行恢复（重读/修正/重新登录），不混在业务导航
```

桌面1280px：业务导航独立侧栏或水平nav，账户区在header次级位置；main最多约1100px可读宽度，列表/编辑分区，状态不用堆成一长句。390px：header品牌与账户保留，nav多行换行，不依赖hover或只剩图标；main单列，编辑字段垂直排列，列表转带标签卡片，同一记录只渲染一份可交互DOM。只有确实需要对比的候选摘要表可局部滚动，行编辑仍单列。长ID/远端名/配置标记换行，不截掉唯一识别信息；所有详情、取消、保存不被固定底栏覆盖。

沿用hash安全页标识；新增上游/模型详情只带公开对象ID或alias（正确编码），完整请求ID保持原内存交接/手动查询，不写URL。Back/Forward/刷新恢复安全页但不恢复凭据、提示词、输出、原始响应或生成操作。非法页回概览并提示；对象404就近返回列表，不替换成另一条。页面标题与当前导航 `aria-current` 一致，跳页焦点到h1。

账户菜单仅放“会话状态”“重新确认会话”“退出”；会话已过期／网络确认失败在当前任务顶部给恢复框。重新登录只返回安全页，不重发核验、保存、签发或生成；退出先取消并清秘密，再确认注销。页脚不展示Go/SQLite、夹具、验收阶段等工程说明；可提供真实“使用帮助”入口。

## 2. 概览：待完成动作与成功详情

```text
概览
下一步：{尚未保存可参与上游 → [添加上游] /
         尚无完整公共模型 → [配置公共模型] /
         尚无启用应用密钥 → [签发应用密钥] /
         尚无当前范围成功证据 → [发起一次调用]}
接入配置：{N个上游，M个启用且凭据完整} [管理上游]
公共模型：{N个启用模型，M个具有完整启用候选} [管理公共模型]
最近一次可核对成功：{公共名 · 上游名称 · 已完成} [查看这次请求]
  <details>证据详情：完整Request ID、调用时间、配置范围、运行范围</details>
  {未知/无当前范围成功，不显示“已健康”}
<details>已完成的准备步骤 → 上游 / 公共模型 / 应用密钥</details>
```

每步只出现一处编号或不用编号；已完成折叠回看，保留入口但不占据首屏大段。下一步按配置依赖选择，不把未核验当强制不能调用，核验可选动作在上游旁。所有计数是SQL真实统计，读取失败显示“暂无法读取”，不是0。手动停用/全部冷却时在调用入口旁解释当前不可参与原因与修正入口，不把配置完整等同供应商健康。

成功摘要、详情和行动绑定同一call_evidence对象；null、degraded、读取失败或未完成响应时清旧行动身份，不显示上一成功为当前。展开详情呈“调用时间：本地可读日期/时间（含时区）”，另可查原RFC3339；配置范围直接显示返回值，不用Date.now或当前配置代替旧事件。字段未知显示未知，不把null当0。服务重启后允许无当前成功证据，历史仍可查。

## 3. 上游列表、详情与编辑

```text
上游                                   [添加上游]
名称 | 手动状态 | 凭据 | 连接核验（时间） | [查看/编辑] [核验连接]
空：尚未接入上游。保存只保存配置。 [添加第一个上游]

上游：团队供应商A                         [返回上游]
名称、地址、启用/停用、凭据已配置/未配置
连接核验：{未核验/核验中/成功/失败/未知} + 完成时间
适用配置与旧核验历史 <details>
生成情况：按公共模型候选列最近结果/未知/冷却至/待重新尝试
[编辑配置] [核验连接] [查看关联公共模型]
```

名称是主识别，地址允许管理员详情可见但不当公开诊断标签。列表每条状态独立，A核验失败不能污染B。禁用为中性“已停用”，不是“连接失败”；凭据只显示存在状态，不能回显星号充当真实token。核验、生成和手动状态各有文字标签，不合成一个绿点。

编辑在详情内展开（新建是独立安全页），顺序：名称→接口地址→凭据password输入及显示/隐藏→启用checkbox→说明→保存/取消。地址标签写“接口基础地址（已包含/v1）”，沿用规范化规则。凭据说明“同地址编辑留空保留；变更地址请重新输入凭据”。创建默认启用，默认无核验；编辑不暗改既有启停。密码显隐按钮type=button，取消表单不提交。

校验按字段进行：空/重名、非法地址、变址缺新凭据就近说明；焦点到首错误，`aria-invalid`+`aria-describedby`；顶部错误摘要可链接到字段。失败保留名称/地址/启停，清本次凭据并提示重新输入，不清另一上游编辑。取消恢复服务器最后已确认值并清凭据；如有草稿离开先提供“返回修改／放弃未保存输入”，不把确认当再次提交。

保存成功→清凭据→详情显示“配置已保存；连接尚未核验”或对应现有核验；焦点到状态区域，给予“核验连接”下一步。保存200后GET失败呈“已保存，最新状态读取未确认”，只提供重读；写响应网络丢失呈“保存未确认，请先重新读取”，不自动PATCH/POST。revision冲突显示“配置已变更，重新读取后再编辑”，保留非敏感草稿供对比，不能覆盖新配置。

停用/启用在编辑保存中完成；停用前旁注“保存后不再开始新尝试；已开始的调用可能完成”。停用不能取消冷却，也不能由核验成功自动启用。列表分页从真实next_cursor前进，读失败保留旧列表并标“非最新”，无下一页时不显示假按钮。

## 4. 连接核验：显式、有界、费用独立

动作旁固定显示：“只检查连接与模型列表，不发起生成；供应商可能对接口访问收费；不能证明目标模型能生成”。这段与按钮在同一任务区域，两屏都可见，不仅放帮助页。

核验点击同步锁本上游动作；显示“正在核验连接（最多10秒）”及[取消核验]，其他只读操作仍可用，同一上游核验按钮禁用；后端409去重结果呈“该上游已有核验进行中，可读取状态”，不启动第二项。退出、过期、跳页先abort该操作；迟到结果不恢复状态。

合法列表返回且成功落盘→“连接与模型列表核验成功”，显示完成时间、执行配置范围；401/403→“凭据未被上游接受，编辑凭据”；429→“上游限制访问，请稍后显式核验”；超时→“核验超时，检查地址或网络”；协议错误→“模型列表格式不符合约定”；取消/无法可靠取终态→“结果未知，重新读取或另行显式核验”。错误正文不展示。改地址/凭据后当前为未核验，旧成功放历史并标旧配置；编辑名称不无故丢当前核验。核验失败/成功均不清生成冷却。

## 5. 公共模型列表、候选编辑与说明

```text
公共模型                               [添加公共模型]
公共名 | 启停 | 可参与候选/总候选 | 最近生成状态 | [查看/编辑]
空：先保存上游，再把它们关联为应用使用的公共名。 [管理上游] [添加]

公共模型：team-chat（应用始终用这个名称）      [返回列表]
启用 [ ]
候选A：上游 [供应商A ▾]   远端模型 [a-chat]
       启用[✓]  优先级[10]  同级权重[1]  [移出候选]
       当前：{未知/最近成功/最近失败/冷却/待重新尝试}；[查看上游]
候选B：上游 [供应商B ▾]   远端模型 [b-chat]
       启用[✓]  优先级[0]   同级权重[1]  [移出候选]
[添加候选]                         [保存模型] [取消]
路由说明与当前选择原因 <details>
```

创建公共名可输入，编辑公共名只读并说明“创建后不改名”；无需新模型独立ID。候选上游选择器显示名称与手动状态，停用对象可保留编辑但不可参与；不能让上游名字冒充id。远端名允许手工输入，不能把连接列表核验升级为生成可用证明；本轮不增自动获取模型或加载页请求供应商。无上游时添加候选不可用，给保存上游入口，不建假候选。

第一条“添加候选”焦点到上游选择；后续自动选项只做草稿、不保存。候选字段有具名label，例如“供应商A 同级权重”，行关联稳定上游ID，UI临时行键仅区分未保存草稿。移出是草稿变化、零写，焦点移到前一行或添加按钮；最后一行移出可保存零候选，但必须标“未就绪；当前不能生成”，保留别名便于后续修复。新候选默认启用、priority0、weight1。

表单始终就近显示：“优先级0–100，数值越大越先选；只有同级才按权重1–100平滑轮流；权重不是健康评分，停用请用启停。”及“先跳过停用、缺凭据、冷却和本请求已试上游；最多顺序尝试3个不同上游，输出或取消后不换”。跨候选费用提醒：“有限切换可能产生多次调用费用；网络失败也可能已经执行。”详细60/30/60/300秒边界可展开，不能把整体上限当单次供应商SLA。

本地及服务端都拒绝重复上游、空远端名、未保存引用、priority -1/101/小数/非数、weight0/101/小数/非数。数字控件min/max/step=1但服务端仍校验；保存前按全部行验证，不让部分行已保存。取消恢复整组，失败保留所有非敏感候选输入就近纠正；保存回读失败与冲突处理同上游。健康不是可写字段，用户只能改配置／启停。

路由解释默认可读句：“先用优先级10的A；A停用/冷却/本请求已试后才考虑B。”同级：“A权重1、B权重3，稳定且无其他流量的长期发起分配约1:3；单次不保证概率”。冷却有完成时间+到期时间和“到期只允许下一个新请求参与，没有后台生成”；已全部冷却给“暂无法参与；等待到期或修正配置”，没有“立即重试绕过”按钮。手动刷新只是GET。

升级特殊状态：无旧上游的历史公共名显示“尚未关联上游，原远端名已保留”；编辑把该原名作为可见迁移提示/草稿建议，管理员显式关联并保存，不从页面加载自动创建供应商。

## 6. 调用测试与逐尝试请求详情

调用测试延续选择公共名、应用密钥password输入、消息、SSE、[发送一次]、[取消]、可读输出及原始诊断折叠。发送旁明确“可能按规则切换至其他上游并产生重复费用；输出后不自动重放”。按钮不叫“自动修复”，不能在网络错误后自动再发送。配置/列表未知与无可用模型分开，模型列表读取失败可重读。核验未执行不阻断完整候选发送；已知零可参与给就近上游/模型修正入口。

| 阶段 | 反馈和可执行动作 |
|---|---|
| 待发送 | 模型可选，依赖可查，手工输入秘密，发送只在合法输入后可用 |
| 等待首结果 | busy锁，取消可用；不在客户端推断“正在A”，因还没有证据；显示“网关可能有限切换，等待首结果” |
| 接收中 | 逐段文本/工具摘要，标正在接收；取消可用；保留实际已取得Request ID，不把HTTP200当完成 |
| 完整结束 | “调用已完成”，[查看这次请求]绑定同ID；跨上游明细由记录读取，不用客户端猜 |
| 失败/不完整 | 安全中文类别，已收到正文标不完整；清应用密钥/消息，保留可读当前诊断、模型/SSE和ID；[查看这次请求]及修正入口 |
| 取消/离页/失效 | 先abort并清秘密/输出，保留已取得非敏感ID；“已停止本地接收，上游可能已执行并计费”；旧回调不能改变新请求 |

请求详情线框：

```text
这次请求：{完整ID}                          [复制ID] [刷新该请求]
结果：{完成/失败/不完整/处理中/已取消/进程中断}
公共模型、调用时间、应用密钥身份（非明文）、总耗时
成功上游：{仅success有；否则“无已确认成功上游”}
用量：{完整合计 / 已知部分合计且N次未知 / 未知 / 零尝试不适用}
尝试1：A → a-chat | 起止/耗时 | 安全原因 | 输入/输出/total各项或未知
尝试2：B → b-chat | 起止/耗时 | 安全原因 | 输入/输出/total各项或未知
<details>为什么选择/跳过：当时priority/weight、启停/冷却/已试、配置版本</details>
{历史行：历史记录无逐尝试证据；原单次字段与用量原样可查}
```

列表摘要用“失败后切换完成 · 2次尝试”而非长ID/时间/版本句；详情保留完整身份与每次配置范围，切换不伪装一次调用。冷却状态有运行范围，历史不能展示为当前。started或dispatching显示已登记/终态未知，不能伪造供应商已接收；进程中断显示尝试完整性未知。404“暂未找到该ID记录”与503读取失败不同，均不找最新行补位；手动刷新只读，不生成。

中文码：upstream_unavailable→“没有可参与候选”，给上游/模型/等待冷却入口；upstream_attempts_exhausted→“可尝试上游已用尽”，展开各原因；request_timeout→“整次调用时间已用尽”，建议检查耗时再显式新调用；configuration_conflict→重读配置；storage_unavailable→“无法可靠记录或读取，停止新增调用并联系维护者”；management_api_changed→刷新同版本控制台。所有供应商错误原文禁止进入默认反馈。

## 7. 生命周期、空／失败状态与键盘合同

每个编辑、核验、读取和生成操作继续使用 `operationID + sessionEpoch + navigationEpoch`；每个await/catch/finally先校验所有权。一个对象的忙锁不能禁用整个应用；取消和账户失效均同步废止旧owner。非敏感草稿只在当前页面内存，秘密不进URL/localStorage/sessionStorage/日志。会话到期倒计时与长流会话检查延续上一规范，不因为新增操作取消独立expiry watchdog。受控fixture名称在测试证据中标注，不作为产品默认预置供应商。

每页共同状态：loading＝明确正在读取且关键写动作暂不可用；empty＝已成功读取零对象并给真实入口；read_failed＝保留已读安全内容标过时并提供GET重读；saving/checking＝当前动作busy与取消语义；success＝明确具体已确认事实；validation_failed＝就近纠正；network_unconfirmed＝先重读；signed_out＝清秘密且进入登录；degraded＝不允许生成，保留可读安全诊断。不能把失败空状态包装成无配置。

键盘：nav/账户按钮/字段/操作按视觉任务顺序Tab；Enter提交仅合法当前表单，空格切checkbox和details；Esc取消当前编辑/核验时必须有等价可见按钮，不能取消整个会话。表单无模态焦点陷阱；账户菜单打开焦点首项、Esc返回触发按钮。focus-visible保留明显边框；状态 `aria-live=polite`，严重错误用role=alert，流输出不逐token高频播报；复制失败显示可选择文本的替代，不自动写日志。

完整连续键盘检查要求每屏：概览→添加A→错误地址纠正→保存/核验→添加B→模型两候选→非法weight纠正→取消整组→重新编辑保存→应用密钥签发（不截秘密）→复制示例→显式普通/SSE/工具调用→详情→取消等待中调用→故障切换→冷却/恢复→账户过期与重新登录。不能将导航后截图、按钮存在或无横滚单独作为AC-09/10通过；详细矩阵见 [验证交接](routing-validation.md)。
