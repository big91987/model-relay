## 具体能力与操作

1. 管理员进入“模型托管”的模型编辑器，选择“权重（默认）”或“低延迟优先”，保存并重新进入核对。策略持久化，旧数据及未指定策略的新模型仍默认 weighted；旧客户端PATCH不带策略不重置原策略。重启保留策略，近期评分重新学习。
2. 两种策略都先过滤租户/Key授权、启用状态、健康与冷却，只在合格最高可用优先级内选路。低延迟不能越过隔离、非零RPM/TPM、次数、并发或金额预算；未知用量规则不变。
3. 只从正常请求被动学习，不发隐藏探测。普通请求测上游响应体首字节；SSE测首个有意义内容、拒绝或工具函数输出增量，忽略心跳、注释、role-only及空增量，分池计分。它们不是完整生成耗时、用户可见正文时刻或供应商TTFT。
4. 每候选最多32样本，按测量时刻60秒过期，至少3样本后以EWMA（alpha=0.25）排序。每5次同组选择保留一次正常流量探索，无有效评分回退weighted。失败、取消、配置代次变化或旧序列迟到响应不得污染恢复池；长流完成不能使旧测量续期。
5. 在“调用测试”发普通或SSE请求，点击“查看同Request ID日志”，查看选择上游、策略、指标、样本数/年龄/EWMA、探索原因和观测采纳/拒绝依据，并核对同请求费用。未知保持null，不默认记录提示词、回复正文、工具参数或凭据；SSE取消及已输出请求不重放。

实现覆盖Go配置/存储升级、路由与观测水位、控制台API及原生管理UI，配套Go HTTP/SSE/安全回归、真实Go服务浏览器旅程和固定受控实验。沿用原冻结PRD/设计/实验基线，不重写验收条件。
