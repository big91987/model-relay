## 工具基线

先运行正式 make architecture-check：声明规则通过，源码摘要 d67816a9746ed4996cfd26820d018c3f895c21df130386423c37d6dbe1dab28b。再通过已安装 inspect_project 标准入口调用 DeepSeek，11 项检查齐全、5 项候选发现、引用校验通过，状态 review_required。原始模型、标准 JSON/Markdown 和调用记录保留在忽略的 harness-output/architecture-remediation/before/ 中。

| 工具发现 | 本轮处理原则 |
| --- | --- |
| HTTP、SQL 与规则同包 | 先拆出有实际规则、状态和测试接口的模块；不靠增加空层或重排文件制造分层 |
| 路由依赖 HTTP/SQL | 路由模块负责选择、健康、采样和探索；网关负责当前配置读取、授权、请求尝试与持久化适配 |
| Server 汇聚多个状态 | 将路由状态封装到其持有者，通过操作接口访问；不能把多个锁概括成一把锁，也不凭静态代码宣称性能改善 |
| 前端功能共享全局状态 | 按功能逐步隔离状态、请求及清理；保留原页面行为和安全清理契约 |
| 规则只能经 HTTP/SQL 测试 | 已有金额计算、边界判断纯函数，原判断存在过度概括；只处理确实嵌入操作流程的规则，不把数据库查询强行当领域规则 |

## 执行方式

1. 路由策略及运行状态抽为独立 Go 包，HTTP/SQL 留在网关/存储适配；保留配置代次、冷却、探索、样本持久化先于采用等既有顺序。
2. 将独立资源/金额规则放入明确能力模块，由原操作流程调用，事务原子性不拆散。
3. 按前端功能和共享传输职责划分模块，不以文件数量或框架切换作为完成标准。
4. 同步项目规范与 architecture.json，以禁止 HTTP/SQL 依赖、允许方向和公开入口等硬规则约束新边界；新增包与规则同一提交引入。
5. 运行相关回归、完整项目入口及整改后工具复扫。接受、拒绝、部分处理与遗留项分别记录，不按模型发现数判定质量。

## 后续工具链需求

- CI 增量模型评审：根据 PR base/head 聚焦变更及其依赖、调用方和适用规范；不能只检查新增文件。快速依赖规则可继续全仓运行，模型范围与规则范围分别配置。
- 工具链定位：作为可独立安装、被本地命令/CI/平台调用的检查工具，不要求采用 Agent Platform 运行时。当前随仓分发作为验证方式保留；本轮不另行建设发布体系。

## 已实施的边界与复扫

| 基线问题 | 本轮改动 | 复核结论与剩余范围 |
| --- | --- | --- |
| 路由策略与 HTTP/SQL 混合 | internal/routing 持有选择、冷却、探索、样本及派发序列；relay 适配配置与持久化 | 无 HTTP/SQL/第三方库依赖；上游请求构造和 SSE 协议仍在 relay，尚未形成独立适配接口 |
| 额度与金额规则嵌入操作流程 | internal/accounting 接收普通值，负责金额、预留、限额与准入判断；原 SQL 和事务边界保留 | 可以独立验证规则；账单关闭、更正、Key 治理和准入事务仍需后续收敛，未宣称完整 SaaS 分层 |
| Server 直接持有路由 map | 路由状态封装到 Engine，经操作或只读观察访问 | 会话、限流、上游检查与有效时钟仍集中；共享配置锁保留，不声称性能提升 |
| 前端功能共享请求和状态 | shared/transport 负责请求生命周期；features/playground 独立管理表单、调用、流与 dispose；工作台组合公开入口 | 调用测试不读全局 state；其他管理页与旧 app.js 尚未拆分，最终模型仍报告其余管理页职责集中 |

## 工具效果与局限

- 确定规则在整改前已通过，说明它只能约束已声明边界，不能据此识别大包职责混合。新增包未归属时工具确实报 incomplete；补齐归属和方向后恢复通过。
- 在隔离副本向 routing 注入 net/http、向 accounting 注入 database/sql、向 playground 注入工作台反向依赖，三次均返回 violations / exit 1。真实源码未注入这些探针。
- 模型能够指出具体函数、包和切分方向，但基线“规则只能通过 HTTP/SQL 测试”过度概括，未充分区分纯计算与数据加载。中间一轮对整个前端给出 conformant 偏宽，最终复扫又识别出其余管理页集中；模型评判存在波动，仍须人工按实际改动范围复核。
- 独立代码审查发现拆分后日志读取失败提示丢失，已恢复并加入先失败、后通过的回归；原路由恢复测试发现冷却配置被固定在构造时，已恢复原配置读取时机。这些运行行为不能由静态架构工具替代验证。
- 三次实际模型均为 deepseek-flash：整改前 99.239 秒、输入 157782 / 输出 14604 Token；中间 99.712 秒、输入 165613 / 输出 17215 Token；最终 147.122 秒、输入 165630 / 输出 23933 Token。模型输入变大，文件拆分本身不会节省模型费用；未按未知价格估算金额。

现有 CI 默认只跑快速全仓规则；本轮未实现模型 changed/full 开关。后续应支持显式 base/head、变更/删除/重命名及必要调用方和规范上下文，报告必须标注增量范围及缺失证据，不能把增量结果冒称全仓审查。工具独立打包与模型增量模式需在维护源发布，再通过标准升级接入；本仓已安装工具文件本轮无修改。
