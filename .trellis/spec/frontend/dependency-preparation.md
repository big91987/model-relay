# Locked verification dependencies

## Scope and signatures
The product is Go; npm dependencies are testing only. `make verification-deps` runs `npm ci --ignore-scripts --omit=optional --no-audit --no-fund --cache .cache/npm`. Both `make frontend-test` and `make browser` depend on this phony target. `make verify` invokes the Go runner in `tests/verify`, which snapshots the candidate into a new private directory and executes the original ordered gates under internal `make verify-gates`.

## Contract and error matrix
`package.json` and `package-lock.json` pin Playwright 1.59.1, including playwright-core 1.59.1. No version change is required for the clean-install repair. The route-cleanup test loads Playwright's locked server implementation at module import time; it cannot run before npm preparation. Installation failure stops the consumer and returns nonzero. Missing Chromium/system libraries or unavailable HTTP listeners remain failures, never skips. No `NODE_PATH`, global package, manually seeded node_modules or platform-controller workaround is permitted.

## Good, base and bad cases
Good: fresh checkout without node_modules, matching host Chromium and network access runs `make verify` without a manual npm command. Base: independent frontend-test/browser entries prepare the same lockfile; recursive verification may install twice, trading minor cached work for deterministic independent entry points. Bad: installing only at the final browser step after frontend module loading, or catching MODULE_NOT_FOUND to skip route-cleanup.

## Required tests and evidence
`tests/verification/dependencies_test.go` runs make dry-runs in isolated directories without dependencies, requiring install-before-consumer for all three targets and retaining all original gates. Its isolated failed-npm fixture proves fail-fast dispatch only, not real installation/network/browser behavior. It enters the fixed race gate through `go test ./...`. Actual clean npm and frontend execution plus host complete `make verify` are required separately. Record before/after source digest, clean state, full logs and exit codes in the current Run. Never replace native host browser evidence with VM or make dry-run results.

## Wrong versus correct

### Scenario: fixed-entry cold evidence
Trigger: warm node_modules hid an ordering defect; the fixed Connector never executed a recommended Run-specific script. Isolation belongs in the public `make verify`, not coordinator instructions.

Signatures: `run(context.Context) error` snapshots `git ls-files --cached --others --exclude-standard -z`. Only regular relative paths are allowed; symlink/path escapes fail. Ignored dependencies/data are not copied. Original Git history is read-only. Candidate uses new GOCACHE/local npm cache, unset NODE_PATH/NODE_OPTIONS and isolated npm user/global configs. `prepareNPMConfig(directory) error` creates separate empty private `.cache/verification-config/user.npmrc` and `global.npmrc`; `candidateEnv` selects these paths. Never point both configuration layers at `/dev/null`: actual npm rejects double-loading the same file even for `npm --version`. Existing `tests/evidence` binds original/copy identities before/after without a hardcoded source digest.

Contract: each call creates unique ignored `test-results/verification/<UTC>-<unique>/verify.log` and `state.json`. Full log streams to the Connector too. State records measured start, UTC, versions, source identities, local lock resolution, end dependency state, gate/overall exit and log bytes/SHA256. Raw `browser/` files require privacy review, never automatic public upload. Cleanup targets only runtime-owned process groups and temporary directories.

### Scenario: filesystem and auxiliary command boundaries

Signatures: `copyFiles(source, target string, files [][]byte) error` opens both real directory roots with `os.OpenRoot`. `copyFile(source, target *os.Root, name string) error` checks every parent using rooted Lstat, rejects links (even links back inside the source), reads through the source root and creates a new destination with O_EXCL through the target root. Lexical checks alone and Lstat of only the final file are insufficient. Root aliases that are themselves symlinks are rejected; OS-resolved ancestor aliases such as the system temporary directory are not inventory paths. Rooted operations also prevent escapes if a checked parent changes before I/O. Caller owns removal of the candidate on failure; never remove or rewrite an input link to make copying pass.

`captureCommand(ctx context.Context, stage string, requested *exec.Cmd, output io.Writer, state *receipt) ([]byte, error)` supervises each inventory/Git-directory/source-evidence/version/dependency command in a separate owned process group with a two-minute deadline. It tees stdout to the existing redacted log and a separate parsing buffer; stderr goes to the same log, never into JSON parsing. COMMAND_START/END record stage, exit and cancellation; `auxiliary_commands` records actual group absence. Git NUL inventory separators are escaped as `\\0` in the text log only; parsing retains original bytes. Chromium failure forwards its captured stdout/stderr and status/signal/error-code, rather than replacing them with a generic error.

The original `make verify-gates` runs with a twelve-minute deadline, within the existing 900-second host ceiling; no permission or timeout expansion. All commands use the existing execute TERM/5-second wait/KILL/group-absence path. SIGTERM cancels through NotifyContext; final deferred log/state capture and candidate removal still run on normal cancellation. SIGKILL or an external kill of the whole tree may prevent finalization: empty finished_utc, log digest/bytes or cleanup=not_started must remain incomplete, never be repaired into a pass.

Error matrix: source/target root link, any inventory parent/final link, nonregular file, absolute/dot/parent escape or existing target -> reject, no outside copy; auxiliary nonzero -> complete diagnostics and failure; invalid source JSON -> fail after logging raw stdout/stderr; cancellation -> bounded exit, owned group evidence and finalized failed receipt; surviving group -> failure, never cleanup success.

Tests: normal nested copy; outside and inside parent links; source/target root aliases; target parent/final links; copy failure removes owned candidate; source/probe stdout+stderr failures and success JSON with stderr; actual Node spawning an explicitly isolated test Chromium executable with failing stdout/stderr (not real Chromium evidence); cancellation at inventory, Git-directory, evidence, prerequisite and probe, with actual child-PID absence; real SIGTERM to the runner with persisted failed state. All tests remain in the original `go test -race ./...` gate. Wrong: `.Output()` without stderr or a background child outside ctx. Correct: captureCommand plus separate machine stdout parsing and preserved log.

Error matrix: absent tool/copy failure -> nonzero; npm failure -> consumers stop; original gate failure -> exact gate exit and overall failure; source drift or log/state write failure -> fail; SIGINT/SIGTERM -> owned group canceled, partial nonzero; SIGKILL/missing final receipt -> incomplete, not pass. After cleanup, bounded signal-0 checks record owned_group_absent; a still-existing owned group fails acceptance. This checks only the new group, not historical or externally detached processes/ports.

Good: unchanged Connector argv `make verify` produces cold start/full receipt even if original node_modules exists. Base: original dependencies remain untouched. Bad: deleting shared dependencies, hand-preinstalling npm, accepting dry-run/fixture/old warm exit0 as actual cold verification, or changing original expectations.

Required tests: `tests/verify/main_test.go` checks safe copy/env, chunk-boundary redaction, actual subprocess stdout/stderr/nonzero, owned-group cancellation and fixture full receipts/hashes/non-mutation. `TestRealNPMIsolatedConfig` invokes actual npm config resolution and `--version` with separate empty files, without installing dependencies or accessing the registry. Tool prerequisites capture both stdout and stderr into the redacted log; the failed-prerequisite fixture asserts the diagnostic survives and gates never start. `tests/verification/dependencies_test.go` checks public wiring and all original internal gates/order. Fixture receipts and local npm configuration checks are not npm install/browser/network evidence; full host fixed entry and independent QA remain required.

### Scenario: distinguish total deadline from stalled routing work
The fixed runner bounds the original gates at 12 minutes; reaching that deadline is failure, not a browser assertion result. Do not increase limits or optimize native keyboard coverage based only on a last generic stage. `browserPhase(output, name, action)` reports start/end UTC and monotonic elapsed milliseconds for the existing migration/legacy/routing/console/full-console actions without replacing their return errors. `routingProgress(width, sequence).step(operation, action)` records per-call native panel/alias/key/message/stream/send/complete durations; one pending marker after 5 seconds identifies an unfinished operation, with its timer cleared on settlement. Only fixed operation names, width, sequence, UTC, durations and success booleans are emitted. Never include input values, HTTP bodies, headers, credentials or error messages in timing diagnostics. Failover stage labels separately identify fixture setup, request, record action/rendering/counts and cooldown.

Good: use actual host timings to distinguish cumulative native work from one stalled operation, then make the next bounded change based on evidence. Base: no end marker on forced termination remains incomplete. Bad: treating timer fixtures as real browser timing, changing an assertion, using fill/selectOption instead of native keyboard, or extending the deadline before diagnosis. `routing-progress.test.mjs` proves value/error identity, whitelist-only output and actual pending timer cleanup; `TestBrowserPhasePreservesResult` verifies one action invocation, unchanged error and no error text leakage. All enter the unchanged fixed gates. Timing diagnostics are not a green receipt or a product fix.
Wrong: `frontend-test: node --test ...` while only browser installs npm. Correct: `frontend-test: verification-deps` and `browser: verification-deps`, sharing exactly one locked install recipe. Chromium provisioning remains an explicit documented host prerequisite, using the installed `./node_modules/.bin/playwright install chromium`, not an unpinned npx download.

### Scenario: native summary attribution before changing synchronization
Execution18 failed at the 1280px model-toggle summary after cold Go/routing/console gates. Production `edit` closes the dialog before awaiting `syncTenants()` and `renderPage()`. That ordering is a possible driver race, not proof of this native failure. Successful PATCH/closed editor cannot prove refreshed table facts.

Signatures: `summaryCell(row,label,expected)` keeps exact unique-row, column-presence and value assertions with no polling/retry. `summaryFailureFacts(error)` records only boundary (`row-count`, `column-present`, `cell-value`), counts, booleans and allowlisted model status (`启用`, `停用`, `other`) in a WeakMap; rethrow the original error. No raw values, labels, IDs or assertion messages enter receipts. Native failed receipt adds these facts and a `content_loading` boolean; stack projection accepts only `tests/browser/{journeys,console-summary}.mjs` and numeric position, never raw stack/host paths.

Matrix: zero/ambiguous row -> failed count retained; missing column -> failed presence retained; stale/wrong status -> failed equality retained; locator error -> same error identity and last measured boundary; unrelated error -> unavailable. Required Node regressions exercise all boundaries and private-value exclusion in the original wildcard frontend gate. They prove diagnostics only, not browser scheduling or a product fix. Good: original host assertion fails with safe exact boundary. Base: non-summary failures report unavailable. Bad: replace the native step with a fixture, dump DOM/error strings, extend deadline or weaken value equality. The next exact-source host `make verify` must produce actual attribution before choosing a synchronization/product repair.

### Scenario: bounded scheduling of isolated Go regressions
Signature: the fixed test recipe is `go test -race -count=1 -v ./... -parallel=4`. The runner still creates empty private Go/npm caches and retains the twelve-minute gate deadline. No test result cache or password-cost override is introduced. `TestCleanVerificationDependencyOrder` requires this bound as well as all original gate commands.

Only independent fixtures opt into `testing.T.Parallel()`: routing temporary-status allowlists, upstream failures/timeouts, connection header/body budgets, resource-matrix tenant/key dimensions, SSE DONE terminal modes, and separate people/summaries scenarios. `installation`, `newConsoleFixture`, and `governedInstallation` create a new temporary SQLite installation for each opted-in test; actual HTTP fixtures own ephemeral listeners with test cleanup. Go module language semantics bind range variables per iteration. Never parallelize steps sharing one fixture, mutate default transports or process environment, lower hash cost, skip real waits, change UTC/budget logic, or adjust expected outcomes for speed.

Matrix: owned fixture + original assertions -> eligible; shared database/server/clock/global configuration -> keep sequential; race/error/timeout -> failure, never retry into acceptance. Required checks: compare the same status-code assertions before/after with actual race executions; run selected in-process fixture combinations together; retain actual HTTP variants in the complete fixed host gate. Local no-listener tests cannot validate those HTTP variants or browser mechanisms. Parallel parent's `0.00s` is not an elapsed-time win; use package wall-clock results. A faster local subset is not proof that complete cold verification fits its deadline.
